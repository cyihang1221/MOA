complete_workflow_description: FLASHQuant is a software tool for intact proteoform quantification from centroided LC-MS1 data, consisting of two main stages: feature group detection and quantity calculation. In the feature group detection stage, m/z traces (individual ion chromatograms) are first extracted from LC-MS spectra using MassTraceExtractor — a self-consistent kernel density estimator that connects peaks within instrument-specific mass accuracy tolerance along retention time; this extraction is performed before deconvolution to reduce noise and uses sliding-window binning of total retention time. Extracted m/z traces are then deconvolved per window and assembled into feature groups (representing putative proteoforms and their isotopes) using FLASHDeconv, which applies both charge and isotope deconvolution to assign monoisotopic masses. During this step, m/z traces may be assigned to multiple feature groups, resulting in 'shared' (overlapping) traces. In the quantity calculation stage, FLASHQuant resolves shared m/z traces via conflict resolution: for each shared trace, theoretical elution profiles (shapes) are estimated for its conflicting feature groups using only their non-shared m/z traces fitted to an exponential-Gaussian hybrid (EGH) function; the contribution of each theoretical shape to the shared trace is then estimated via non-negative least-squares optimization, enabling proportional distribution of the shared trace’s abundance among the corresponding feature groups. Finally, feature group abundance is calculated as the summed area under all constituent m/z trace curves. FLASHQuant outputs results in TSV format, including monoisotopic mass, retention time range, charge range, and quantity for each feature group. Additionally, the ConsensusFeatureGroupDetector tool is provided to identify feature groups consistently detected across multiple LC-MS runs (e.g., technical replicates) using user-defined mass and retention time tolerances (default: 20 ppm mass, 8 min RT), and supports input from other quantification tools (e.g., TopFD) when column names for mass, apex RT, and quantity are specified. Parameters used in benchmarking included those from ProSightPD (100 ppm mass tolerance, 8 min RT tolerance for consensus detection), and all runtime and performance comparisons were conducted on a desktop PC with Intel(R) Core(TM) i9–7900X CPU @ 3.30 GHz and 64 GB RAM.

sample_description: The benchmark data set used in the research is from the iPRG-2015 study, consisting of four biological samples (yeast cell lysate with spike-ins of six different purified proteins at varying concentrations), each analyzed in three technical replicates, resulting in 12 LC–MS/MS runs total. complete_workflow_description: The method involved multiple integrated software components and sequential analytical steps: (1) Data preprocessing: Raw mzML files were processed using OpenMS tools — PeptideIndexer and IDFilter for ID annotation and decoy removal; MapAlignerIdentification (lowess) for RT alignment of external IDs to internal references; IDMerger for merging aligned ID sets. (2) Feature detection: FFId was executed in three strategies: (i) 'Internal IDs only': FFId used only run-specific internal IDs to generate assays (RT windows derived from ID RTs, theoretical m/z for up to 2 isotopologues), extract XICs via OpenSWATH (10 ppm m/z window, 40 s RT range), detect peak groups (Gaussian smoothing + local maxima detection + cross-XIC grouping), select features by ID-matching count (tie-breaking by intensity), and fit Gaussian elution models (Levenberg–Marquardt least-squares) to compute feature intensities.
