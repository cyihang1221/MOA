========== paper_workflow entry 1 ==========
related_tool: ProteoWizard
sample_description: The samples used in the research were grab samples collected from the effluent of a wastewater treatment plant in Warburg, Germany (Stadtwerke Warburg GmbH). These effluent samples contain a high organic load, resulting in pronounced matrix-associated effects in high-resolution mass spectrometry (HRMS), such as signal overlay—making them particularly suitable for robustness testing of the centroiding algorithm. The sampling and sample preparation protocols followed those detailed in Hohrenk et al. (2020) [24]. The samples were analyzed using HPLC-HRMS for both MS1 and MS2 spectra, with all illustrative examples in the paper focusing on MS1 spectra acquired in electrospray ionization positive mode (ESI+); however, the algorithm is explicitly designed to support both ESI+ and ESI− measurements. Importantly, the chromatographic domain was intentionally neglected during algorithm development—i.e., spectra were treated as independent observations—to ensure universal applicability regardless of whether prior chromatographic separation was performed.
complete_workflow_description: The centroiding process consists of five core computational stages implemented in Python, R, and Julia: (1) Input parsing—loading profile-mode *.mzXML spectra; (2) Peak isolation—identifying individual peak profiles using zero-intensity boundaries (for resolved peaks) and valley-point splitting (for overlapping peaks), without deconvolution; (3) Log-transformed Gaussian regression—applying Caruana’s linearization method via second-order weighted linear regression on ln(I(x)) to estimate Gaussian parameters (peak position x̂₀, height Î₀, width σ̂) using equations (2)–(5); weights wᵢ = Iᵢ / ΣIᵢ² (squared intensity normalization) are applied to mitigate noise bias; (4) Sparse matrix algebra—solving the weighted least-squares problem β̂ = (XᵀWX)⁻¹XᵀWY using sparse Vandermonde matrices X (n × m, where n = data points per spectrum, m = number of isolated peaks) to enable memory-efficient, parallelized computation; (5) Data Quality Score (DQS) calculation—deriving DQS = 1 − erf(ΔÂ/Â) using error propagation on Â = Î₀·σ̂·√(2π) (Eq. 6), where ΔÂ incorporates standard errors of Î₀ and σ̂ obtained from the variance–covariance matrix s̆²(β) = MSE·(XᵀWX)⁻¹ (Eq. 12), and MSE = (1/(n−3))·Σwᵢ(yᵢ − ŷᵢ)² (Eq. 13); peaks failing β̂₂ < 0 or having <4 data points are rejected. Final outputs are exported as comma-separated value (*.csv) files containing centroided m/z–intensity pairs along with associated DQS values and parameter uncertainties. Supplementary implementation details for TOF-MS (using Bi-Gaussian modeling) and validation datasets (e.g., Samanipour et al., 2021 [23]) are provided in the SI.

========== paper_workflow entry 2 ==========
related_tool: ProteoWizard
sample_description: The research utilized a broad spectrum of proteomics and metabolomics data sets from different laboratories, encompassing various mass spectrometry (MS) techniques and instruments from major vendors including Thermo, Agilent, Sciex, and Waters. Specifically tested data types included SWATH-DIA, DDA (data-dependent acquisition), and selected reaction monitoring (SRM). Twelve representative data files were selected: files 1–4 from reference (8), files 5–8 from reference (15), file 9 from reference (16), file 10 from reference (17), file 11 from reference (18), and file 12 from reference (19). Two key validation data sets — 'AgilentQToF' and 'QExactive' — were used for detailed performance and downstream workflow analysis (e.g., Mascot peptide search and protein inference). All vendor raw files were converted to mzMLb using the msconvert tool from ProteoWizard.
complete_workflow_description: The method involved designing and implementing mzMLb — a binary extension of the PSI-standard mzML format — using HDF5 as the underlying container. Key procedural steps include: (1) Storing numerical data (e.g., m/z values, intensities, chromatogram start times) in native HDF5 datasets (e.g., 'spectrum_MS_1000514_double', 'spectrum_MS_1000515_float') instead of Base64-encoded XML <binary> tags; (2) Embedding full mzML XML metadata inside an HDF5 character array dataset named 'mzMLb', modified such that <binary> tags contain only attributes specifying the HDF5 dataset name and byte offset (not embedded binary data); (3) Replacing mzML index structures (<indexed mzML>) with native HDF5 one-dimensional 64-bit integer arrays ('mzML_spectrumIndex', 'mzML_chromatogramIndex'); (4) Applying a lossy but highly controlled coding scheme combining three components: (a) mantissa bit truncation (e.g., reducing double-precision 52-bit mantissa to fewer bits, conservatively capped at ≤21 bits removed to maintain <2×10⁻⁹ relative error for m/z and <2×10⁻⁴ for intensities), (b) HDF5 shuffle filter to rearrange bytes for improved zero-run compressibility, and (c) 'mzLinear' linear extrapolation predictor — storing only the residual error Δh = yₙ₊₂ − (2yₙ₊₁ − yₙ) — optimized for quadratic m/z relationships (e.g., time-of-flight MS); (5) Integrating optional compression backends: zlib (for high-ratio lossless/lossy compression) and BLOSC with LZ4HC (for ultra-fast, low-overhead compression targeting speed-critical use cases); (6) Empirically optimizing HDF5 chunk size across 16 KB to 2048 KB ranges, identifying 1024 KB as the default balancing compression ratio, write speed, and random read latency; (7) Validating downstream impact via Mascot PSM search and protein inference workflows on AgilentQToF and QExactive datasets, comparing peptide/protein lists, E-values, and score deviations against uncompressed originals and Numpress-compressed controls.

========== paper_workflow entry 3 ==========
related_tool: ProteoWizard
sample_description: The study used two main experimental datasets: (1) a bovine spike-in experiment involving an equimolar six-bovine-protein tryptic digest (Bruker-Michrom) spiked at nine concentrations (48, 16, 4, 2, 1, 0.5, 0.25, 0.05, and 0.025 fmol/μL) into a constant background matrix of digested S. cerevisiae soluble lysate (0.75 μg/μL), where the yeast digest was prepared from 400 μL of 5.1 μg/μL BY4741 strain proteins solubilized in 50 mM ammonium bicarbonate (ABC), reduced with 6 μL 500 mM TCEP at 60°C for 30 min, alkylated with 8 μL 500 mM iodoacetamide for 30 min at RT, quenched with 5 μL 500 mM DTT for 15 min at 37°C, and digested with 40 μL of 2 μg/μL TPCK-treated trypsin for 4 h at 37°C, followed by acidification with 60 μL 10% TFA; and (2) a comparative proteomics experiment using rapamycin-treated yeast (S. cerevisiae), though specific sample preparation details for the rapamycin experiment were not provided in the text. All samples were analyzed via nanoLC-MS/MS using 2 μL injections.
complete_workflow_description: The primary software-based analytical procedure involved demultiplexing of overlapping-window DIA data using a custom non-negative least squares algorithm implemented in both Skyline (v23) and ProteoWizard msconvert (v24). The demultiplexing process was applied on-the-fly during data analysis in Skyline for fragment ion extraction and also used in ProteoWizard msconvert to generate fully demultiplexed spectra files. The algorithm takes as input raw profile-mode MS/MS spectra acquired under overlapping 20 m/z window DIA (e.g., odd cycles: 500–900 m/z; even cycles: 490–890 m/z), identifies spiky vs. smooth chromatographic patterns across adjacent scans to distinguish left/right demultiplexing region contributions, constructs the system XA = Y using 41 demultiplexing regions (490–900 m/z, 10 m/z each), and solves it via Lawson-Hanson non-negative least squares with heuristic block-wise approximation for speed. Downstream quantification and detection used Skyline for peak integration, mProphet (v25) for peptide detection scoring (with decoy reversed peptides, q < 0.01 FDR cutoff, features including intensity, retention time difference, library dot-product, co-elution, signal-to-noise, mass errors, and shape scores), MSStats (v3.10.2) for lower limit of quantification (LoQ) estimation, and Crux (v30) with Comet (v2015.01 rev2) and Percolator (v2.09) for database searching of DDA and QC runs. Normalization used 81–86 high-intensity, robust yeast background peptides selected from DDA runs on unlabeled yeast lysate, with peak areas summed per run and used to normalize spike-in peptide intensities across all acquisition methods (10 m/z, 20 m/z, 20 m/z overlap with/without demux).

related_tool: ProteoWizard
sample_description: The sample consisted of three proteomics datasets derived from maize kernels with peroxidase (POD) activity: (1) 2DM — a protein spot excised from 2D gel electrophoresis; (2) 1DM — a protein band from 1D gel electrophoresis of partially purified peroxidase; and (3) 1DR — a protein band with peroxidase activity from recombinant expression of a putative peroxidase (cloned from cDNA) in Escherichia coli. The biological objective was to identify candidate peroxidases involved in post-harvest insect resistance of maize kernels.
complete_workflow_description: The proteomics workflow was implemented using Taverna Workflow Management System (WMS) on MASSyPup64. The procedure comprised the following sequential steps: (1) Peptide identification using Comet (v2015 or later) with parameters defined in a comet.params file located in the same directory as the mzML input files; key settings included database_name pointing to a protein/DNA database, decoy_search = 1 for concatenated decoy search (eliminating need for separate decoy DB generation), and default search tolerances implied by Comet’s standard configuration. (2) Validation of peptide-spectrum matches using PeptideProphet (Keller et al., 2002) to generate pep.xml files, followed by ProteinProphet (Nesvizhskii et al., 2003) to infer protein-level confidence and generate prot.xml files — both integrated as simple tool modules from the Trans-Proteomic Pipeline (TPP) 4.8.0, compiled but run locally without the TPP web server. (3) Export of validated results into multiple formats: xls (Excel/Gnumeric-compatible), csv, html, and mzid (mzIdentML standard) using TPP- and OpenMS/TOPPAS-derived tools plus Linux system utilities. (4) Text mining via pattern-matching: extraction of protein hits containing the case-insensitive search string 'eroxidase' (to capture 'peroxidase' while avoiding case-sensitivity issues) into a dedicated CSV summary file. The full workflow is stored at /usr/local/massypup64-taverna-workflows/m64-comet-val-export.t2flow and requires two inputs: the data path (e.g., /usr/local/massypup64-examples/Maize-Proteomics-PODs) and the search string. Acceptance criteria for final candidates were set post-hoc to ≥2 unique peptides and ProteinProphet probability ≥0.95.

complete_workflow_description: The process procedure involved two main experimental evaluations using RawConverter: (1) Monoisotopic peak selection for DDA data and (2) Precursor prediction for DIA data. For DDA evaluation: RawConverter (alongside RawXtract v1.9.9.2, pXtract v2.0 with pParse, and ProteoWizard v3.0.7162) extracted 37,532 tandem mass spectra from a Thermo Velos LTQ Orbitrap RAW file; all extracted MS2 files were searched using IP2 (ProLuCID + DTASelect 2) with identical parameters: 50 ppm precursor/600 ppm fragment tolerance, semi-tryptic peptides, one missed cleavage, carbamidomethylation (Cys) fixed, oxidation (Met) and deamidation (Asn/Gln) variable (≤1 per peptide), and 1% PSM-level FDR via target-decoy. For DIA evaluation: DIA raw files were acquired on a Thermo Fisher Q Exactive using isolation windows of 3, 5, or 10 m/z across 400–1200 m/z; RawConverter processed these to generate DDA-like MS2 files—either with predicted precursors (reporting top-N monoisotopic m/z and charge states per spectrum, where N is dynamically determined by window width) or without prediction (defaulting to charge states 2 and 3, with precursor error tolerances set to 4.5 Da, 7.5 Da, and 15 Da respectively). These files were searched using IP2 with adjusted parameters: 50 ppm precursor/100 ppm fragment tolerance, DTASelect 2 precursor delta mass cutoff of 10 ppm, and same modification and FDR settings. All searches used the UniProt human database and target-decoy strategy.

complete_workflow_description: The process procedure involved four core signal processing steps applied consistently across all datasets: (1) Peak-picking of MS/MS spectra using CantWaiT via msConvert; (2) Precursor m/z assignment and monoisotopic peak identification using Turbocharger via msConvert, operating on survey scan data adjacent to each MS/MS spectrum; (3) Deisotoping of MS/MS spectra using ProteoWizard’s Poisson-based deisotoper via msConvert; and (4) For Waters data only, subscan summation prior to steps 1–3 using msConvert’s built-in algorithm. Following signal processing, peptide database searching was performed using two engines—MyriMatch (multivariate hypergeometric scoring) and MS-GF+ (prefix residue mass graph scoring)—against full proteome-level FASTA databases containing reverse decoy sequences; search parameters included up to two missed cleavages, semitryptic digest, min/max peptide lengths of 5/75 aa, static modifications (carboxymethylation/carbamidomethylation of Cys), dynamic modifications (Met oxidation, Gln ammonia loss, N-terminal Gln/Asn deamidation for Bovine 6), and instrument-specific precursor/fragment tolerances (50/100 ppm except Thermo Q-Exactive: 10/20 ppm); monoisotopic peak misassignment correction was disabled to assess monoisotopic localization accuracy. Search results were assembled into parsimonious protein groups using IDPicker 3.0 with default settings: 2% FDR (Q-value) for PSMs and ≥2 distinct peptides per protein group. Performance was benchmarked against vendor/commercial tools: Thermo and Agilent data used vendor libraries in msConvert (with ProteoWizard deisotoping added), AB SCIEX data used AB SCIEX MS Data Converter (‘proteinpilot’ option), and Waters data used Mascot Distiller (with customized parameters: max charge +8, precursor tolerance ±1.5 m/z, grouping tolerance 0.05 m/z, min mass 1.0 Da, max subscan time 30 s, min peak list size 1).

complete_workflow_description: The end-to-end computational workflow begins with raw LC-HRMS data acquisition from S. cerevisiae extracts (including WT/KO strains, labeled/unlabeled conditions, aqueous/nonpolar fractions, and blanks). Raw files are first converted to mzXML using ProteoWizard v3.0.20022-e71f69e07. Peak detection, deconvolution, and alignment are performed in MS-DIAL 4.8, generating a unified feature table with numeric MS-DIAL IDs. These features are then imported into PAVE 2.0 (MATLAB R2017b GUI) using generated .mat files to perform credentialing—comparing isotopic patterns across unlabeled, 13C-, 15N-, and 13C+15N-labeled samples to identify biologically derived features and assign carbon/nitrogen counts. Credentialed features are merged across strain comparisons (WT vs KO) per experimental setup (SF/D48) using MS-DIAL IDs to eliminate duplicates. The resulting credentialed feature list serves as input for downstream annotation using open-source tools including MetFrag, Shinyscreen, SIRIUS CSI:FingerID, and MetaboAnalyst 5.0. For statistical analysis, credentialed peak heights are normalized to an internal standard (4-chloro-L-phenylalanine), Pareto-scaled, and subjected to PCA in MetaboAnalyst; additional statistical testing (ANOVA with FDR correction and Tukey’s HSD) is performed in R. All parameter settings and intermediate files are archived in the ESM and Zenodo repositories.

complete_workflow_description: The end-to-end metabolomics workflow began with serum sample collection from 102 asthmatic patients and 18 healthy controls. Raw LC-MS/MS data files were converted to mzXML format using ProteoWizard (v3.0.19282), then processed in R using the 'XCMS' package for peak detection, extraction, alignment, and integration. Multivariate statistical analysis was performed using SIMCA (v14.1): PCA for unsupervised exploration and OPLS-DA for supervised discrimination between groups; metabolites with VIP > 1 and univariate p < 0.05 were deemed significantly different. Metabolite annotation was conducted using BiotreeDB (v2.1) with a similarity cut-off of 0.3. WGCNA was performed in R using the 'WGCNA' package on 827 MS2 metabolites, with soft threshold power = 4, dendrogram cut height = 0.25, and minimum module size = 30; hub metabolites were defined as those with gene significance (GS) > 0.2 and module membership (MM) > 0.8. Overlap between OPLS-DA-derived differentially metabolized compounds (DMs) and WGCNA-derived module-associated metabolites yielded 116 asthma-associated metabolites, including 12 hub metabolites. Pathway enrichment analysis was carried out using the KEGG database, identifying sphingolipid metabolism and valine/leucine/isoleucine biosynthesis as significantly enriched. Finally, two hub metabolites—myristoleic acid and dodecanoylcarnitine—were validated in an independent cohort using UHPLC-MS/MS.
