</div></section></section><section aria-label="Article content"><section class="body main-article-body"><section class="abstract" id="abstract1"><h2>Abstract</h2>
<p id="P1">The field of computational proteomics is approaching the big data age, driven both by a continuous growth in the number of samples analysed <em>per</em> experiment, as well as by the growing amount of data obtained in each analytical run. In order to process these large amounts of data, it is increasingly necessary to use elastic compute resources such as Linux-based cluster environments and cloud infrastructures. Unfortunately, the vast majority of cross-platform proteomics tools are not able to operate directly on the proprietary formats generated by the diverse mass spectrometers. Here, we present ThermoRawFileParser, an open-source, cross-platform tool that converts Thermo RAW files into open file formats such as MGF and the HUPO-PSI standard file format mzML. To ensure the broadest possible availability, and to increase integration capabilities with popular workflow systems such as Galaxy or Nextflow, we have also built Conda package and BioContainers container around ThermoRawFileParser. In addition, we implemented a user-friendly interface (ThermoRawFileParserGUI) for those users not familiar with command-line tools. Finally, we performed a benchmark of ThermoRawFileParser and msconvert to verify that the converted mzML files contain reliable quantitative results.</p></section><section id="S1"><h2 class="pmc_sec_title">Introduction</h2>
<p id="P2">The field of computational proteomics is approaching the big data age (<a href="#R1" class="usa-link" aria-describedby="R1">1</a>), driven both by a continuous growth in the number of samples analysed <em>per</em> experiment, as well as by the growing amount of data obtained in each analytical run. At the same time, more data is now publicly available in proteomics repositories, which in turn means that there is increasing benefit to be had from the reanalysis of millions of mass spectra (<a href="#R2" class="usa-link" aria-describedby="R2">2</a>–<a href="#R5" class="usa-link" aria-describedby="R5">5</a>) to find new biological insights (e.g. novel variants and post-translational modifications (<a href="#R6" class="usa-link" aria-describedby="R6">6</a>)). However, in order to process these large amounts of (public) data, it is increasingly necessary to use elastic compute resources such as Linux-based cluster environments and cloud infrastructures (<a href="#R7" class="usa-link" aria-describedby="R7">7</a>).</p>
<p id="P3">The development of computational proteomics tools has historically been favoured the Microsoft Windows operating systems with tools such as ProteomeDiscover, MaxQuant (<a href="#R8" class="usa-link" aria-describedby="R8">8</a>), PeaksDB and Mascot Distiller (<a href="#R9" class="usa-link" aria-describedby="R9">9</a>). An important driver for this bias has been the lack of cross-platform libraries to access instrument output data files (RAW files) from major instrument providers (<a href="#R10" class="usa-link" aria-describedby="R10">10</a>). Several approaches have been devised to overcome this challenge, including the use of dedicated Windows machines in workflows (<a href="#R11" class="usa-link" aria-describedby="R11">11</a>) for conversion to RAW data to standard file formats such as mzML (<a href="#R12" class="usa-link" aria-describedby="R12">12</a>), the encapsulation of Windows tools such as ReAdW (<a href="#R13" class="usa-link" aria-describedby="R13">13</a>) and msconvert (<a href="#R14" class="usa-link" aria-describedby="R14">14</a>) into WineHQ (<a href="http://tools.proteomecenter.org/wiki/index.php?title=Msconvert_Wine" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">http://tools.proteomecenter.org/wiki/index.php?title=Msconvert_Wine</a>) to make these tools Linux-compatible, and even the creation of reverse-engineered RAW file readers (<a href="#R15" class="usa-link" aria-describedby="R15">15</a>).</p>
<p id="P4">An important breakthrough was achieved in 2016, when Thermo Scientific released the first cross-platform application programming interface (API) that enables access to Thermo RAW files from all their instruments on all commonly used operating systems (e.g. Linux/Unix, Mac OX or Microsoft Windows). Importantly, this provides the enticing possibility to move proteomics into Linux/UNIX environments, including scalable clusters and cloud environments. This library has already led to a new version of the popular MaxQuant framework that is compatible with Linux/UNIX environments (<a href="#R16" class="usa-link" aria-describedby="R16">16</a>), and it has also been incorporated into the cross-platform, cluster-oriented quantification tool moFF (<a href="#R17" class="usa-link" aria-describedby="R17">17</a>).</p>
<p id="P5">While the Thermo cross-platform library thus enables specially-developed software to access Thermo Raw files on diverse operating systems, most open-source computational proteomics workflows (e.g. OpenMS (<a href="#R18" class="usa-link" aria-describedby="R18">18</a>), Galaxy (<a href="#R19" class="usa-link" aria-describedby="R19">19</a>), and the Trans-Proteomics pipeline (TPP) (<a href="#R20" class="usa-link" aria-describedby="R20">20</a>)) are based on generic, open data formats such as Mascot Generic File (MGF) or mzML. In order to allow these tools to benefit maximally from the cross-platform access to Thermo Raw files, we here present ThermoRawFileParser, an open-source, cross-platform tool that converts Thermo RAW files into open file formats such as MGF and mzML similar to other tools such as msconvert (<a href="#R14" class="usa-link" aria-describedby="R14">14</a>) and RawTools (<a href="#R21" class="usa-link" aria-describedby="R21">21</a>). To ensure the broadest possible availability, and to increase integration capabilities with popular workflow systems such as Galaxy (<a href="#R22" class="usa-link" aria-describedby="R22">22</a>) or Nextflow (<a href="#R23" class="usa-link" aria-describedby="R23">23</a>), we have also built a Conda package (<a href="#R24" class="usa-link" aria-describedby="R24">24</a>) and a BioContainers (<a href="#R25" class="usa-link" aria-describedby="R25">25</a>) container around ThermoRawFileParser. Finally, we performed a benchmark of ThermoRawFileParser and msconvert to verify that the converted mzML files contain reliable quantitative results.</p></section><section id="S2"><h2 class="pmc_sec_title">Materials</h2>
<section id="S3"><h3 class="pmc_sec_title">Tool Design and Integration</h3>
<p id="P6">ThermoRawFileParser (<a href="https://github.com/compomics/ThermoRawFileParser" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/compomics/ThermoRawFileParser</a>) has been implemented following a modular design (<a href="#F1" class="usa-link">Figure 1</a>). Every file specific exporter is implemented as an independent module, which enables easy extension to include more exporters in the future. Currently, the tool can export to MGF (<strong>MGFSpectrumWriter</strong>), mzML (<strong>MzMLSpectrumWriter</strong>), and JSON (for the metadata only) (<strong>MetadataWriter</strong>). This modular design has already enabled the community to extend the library for other novel file formats such as Parquet (<strong>ParquetSpectrumWriter</strong>), which is designed for distributed big data processing clusters of Hadoop or Spark. The JSON export of ThermoRawFileParser can optionally be used to only extract various metadata elements (including instrument settings and scan settings; see <a href="https://github.com/PRIDE-Archive/pride-metadata-standard" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/PRIDE-Archive/pride-metadata-standard</a>) (<a href="#SD1" class="usa-link">Supplementary Note 1</a>). This specific feature is currently used by the PRIDE Database to re-annotate thousands of RAW files with the correct instrument metadata. For peak picking, data centroiding, and noise removal, ThermoRawFileParser relies on the native methods provided by the Thermo API.</p>
<figure class="fig xbox font-sm" id="F1"><h4 class="obj_head">Figure 1. Modular design of ThermoRawFileParser includes exporters to MGF, mzML, Parquet, and Json Metadata. A Conda package and corresponding BioContainer is available for reuse in workflow engines such as Nextflow, Galaxy and OpenMS.</h4>
<p class="img-box line-height-none margin-x-neg-2 tablet:margin-x-0 text-center"><a class="tileshop" target="_blank" href="https://www.ncbi.nlm.nih.gov/core/lw/2.0/html/tileshop_pmc/tileshop_pmc_inline.html?title=Click%20on%20image%20to%20zoom&amp;p=PMC3&amp;id=7116465_EMS106469-f001.jpg"><img class="graphic zoom-in" src="https://cdn.ncbi.nlm.nih.gov/pmc/blobs/4497/7116465/840b56e0f2df/EMS106469-f001.jpg" loading="lazy" height="577" width="800" alt="Figure 1"></a></p>
<div class="p text-right font-secondary"><a href="figure/F1/" class="usa-link" target="_blank" rel="noopener noreferrer">Open in a new tab</a></div></figure><p id="P7">A key feature of any open-source tool is its ability to integrate with other frameworks (<a href="#R26" class="usa-link" aria-describedby="R26">26</a>). We have therefore created a BioConda recipe (<a href="#R24" class="usa-link" aria-describedby="R24">24</a>) for ThermoRawFileParser (<a href="https://github.com/bioconda/bioconda-recipes/tree/master/recipes/thermorawfileparser" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/bioconda/bioconda-recipes/tree/master/recipes/thermorawfileparser</a>), which can be used to automatically build a Docker Container. This Docker is pushed to the BioContainer project (<a href="#R25" class="usa-link" aria-describedby="R25">25</a>), which in turn enables easy reuse of the tool by both the Galaxy (<a href="#R22" class="usa-link" aria-describedby="R22">22</a>) and the Nextflow (<a href="#R23" class="usa-link" aria-describedby="R23">23</a>) environments. As an illustration of such integration, we have developed a Nextflow workflow for the proteomics community, which converts an entire ProteomeXchange project using the ThermoRawFileParser container (<a href="https://github.com/bigbio/nf-workflows" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/bigbio/nf-workflows</a>).</p>
<p id="P8">In addition to the command-line tool, we have implemented a graphical user interface that makes the use of ThermoRawFileParser easier and highly intuitive, enabling the user to perform conversions of RAW files. The GUI includes all main options of ThermoRawFileParser, and a report system to report errors during the conversion. ThermoRawFileParserGUI is an open source Java program, available in a cross-platform package that incorporates ThermoRawFileParser executables for the main operating systems. It can be downloaded from <a href="https://github.com/compomics/ThermoRawFileParserGUI" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/compomics/ThermoRawFileParserGUI</a>.</p></section><section id="S4"><h3 class="pmc_sec_title">Benchmark datasets</h3>
<p id="P9">Four different datasets and three different Thermo models were used to compare the conversion from RAW files into mzML with the ProteoWizard msconvert tool and the ThermoRawFileParser: PXD014195 and PXD006336 (Orbitrap Q-Exactive), PXD014346 (Orbitrap Fusion Lumos), PXD014772 (Orbitrap Velos).</p></section><section id="S5"><h3 class="pmc_sec_title">IPRG-2015 dataset</h3>
<p id="P10">We used the IPRG2015 dataset (<a href="https://www.ebi.ac.uk/pride/archive/projects/PXD010981" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://www.ebi.ac.uk/pride/archive/projects/PXD010981</a>) (<a href="#R27" class="usa-link" aria-describedby="R27">27</a>) to benchmark the quality of the mzML files produced by ThermoRawFileParser. This dataset is based on four artificially constructed samples of known composition, each containing a constant background of 200ng of tryptic digests of <em>S. cerevisiae</em> (ATCC strain 204508/S288c). Each sample was separately spiked in with different quantities of six individual protein digests. Samples were analysed in three LC-MS/MS using a Thermo Scientific Q-Exactive mass spectrometer (12 runs). Both MS and MS/MS data were acquired in profile mode in the Orbitrap, with resolution 70 000 for MS and 17 500 for MS/MS. The MS1 scan range was 300-1650 m/z, the normalized collision energy was set to 27%, and singly charged ions were excluded (<a href="#R27" class="usa-link" aria-describedby="R27">27</a>).</p></section><section id="S6"><h3 class="pmc_sec_title">Benchmark analysis workflows</h3>
<section id="S7"><h4 class="pmc_sec_title">Identification-free workflow</h4>
<p id="P11">We built a Nextflow (<a href="#R23" class="usa-link" aria-describedby="R23">23</a>) identification-free workflow using OpenMS (<a href="#R28" class="usa-link" aria-describedby="R28">28</a>) to benchmark different metrics such as: number of spectra MS1/MS2, number of peaks by spectrum at MS1 and MS2 levels and the charge state distribution (<a href="https://github.com/bigbio/nf-workflows/tree/master/qc-idfree_from_raw" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/bigbio/nf-workflows/tree/master/qc-idfree_from_raw</a>).</p></section><section id="S8"><h4 class="pmc_sec_title">Identification workflow</h4>
<p id="P12">To perform the benchmarking, we built a workflow using OpenMS (18, 28) in which raw files were converted from Thermo Scientific RAW files to mzML using the msconvert tool from ProteoWizard (<a href="#R14" class="usa-link" aria-describedby="R14">14</a>) on the one hand, and with ThermoRawFileParser on the other hand. The resulting spectra were centroided and searched using MS-GF+ (v2018.01.30) (<a href="#R29" class="usa-link" aria-describedby="R29">29</a>), executed via the OpenMS search engine wrapper MSGFPlusAdapter, allowing 10 ppm precursor mass tolerance, and setting carbamidomethylation of cysteine as fixed, and methionine oxidation as variable modification. All other settings were kept at their default values. PSMs were filtered (q-value &lt; 5%). The workflow for comparison was developed using Nextflow (<a href="#R23" class="usa-link" aria-describedby="R23">23</a>) and BioContainers (<a href="#R25" class="usa-link" aria-describedby="R25">25</a>) to ensure the reproducibility of the present results (<a href="https://github.com/bigbio/nf-workflows/tree/master/benchmark-converter-nf" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/bigbio/nf-workflows/tree/master/benchmark-converter-nf</a>).</p></section></section></section><section id="S9"><h2 class="pmc_sec_title">Results and Discussion</h2>
<p id="P13">We compare msconvert and ThermoRawFileParser conversion to mzML using four different metrics: Number of spectra MS1 and MS2, number of peaks by MS1 and MS2, and the precursor charge distribution (<a href="#F1" class="usa-link">Figure 1</a>).</p>
<p id="P14">The results show major differences between both tools with regards to the number of peaks reported, and this on each MS level (MS1 and MS2). On average, the number of peaks <em>per</em> spectrum is ten-fold higher for msconvert mzML files as compared to ThermoRawFileParser mzML files. This occurs because the new peak picking method implemented in the Thermo API used by ThermoRawFileParser improved drastically with regards to the removal of noise peaks that do not contribute to identification. As a result, despite the substantial difference in the number of peaks retained, there is no major difference in the identification map and precursor charge distribution (<a href="#SD1" class="usa-link">Supplementary Figure 1</a>) between the tools.</p>
<p id="P15">
<a href="#T1" class="usa-link">Table 1</a> shows the number of MS1 and MS2 spectra, and the number of identified peptides and proteins for both workflows. The number of MS1 and MS2 in the mzML files were the same for all RAW files converted with msconvert and ThermoRawFileParser. Across all samples and replicates, the number of identified peptides and proteins is higher for the ThermoRawFileParser workflow when compared to the msconvert workflow, despite the abovementioned higher number of peaks retained in the msconvert workflow. This identification advantage for ThermoRawFileParser derived mzML files amounts to 10% on average at the peptide level, and to 4% on average at the protein level (<a href="#T1" class="usa-link">Table 1</a>). Benchmarking protein quantification between both approaches shows no major differences between the two approaches (<a href="#F2" class="usa-link">Figure 2</a>).</p>

The results show that there is no appreciable difference between the IPRG 2015 analysis and the results from the ThermoRawFileParser workflow (<a href="#F2" class="usa-link">Figure 2</a>).</p>
<p id="P17">In addition to msconvert, the recently published RawTools (<a href="#R21" class="usa-link" aria-describedby="R21">21</a>) allows to convert RAW files into MGF files. In addition, it provides multiple options to perform QC metrics. However, RawTools is not design as a conversion tool and does not provides support for standard HUPO-PSI file formats such as mzML.</p></section><section id="S10"><h2 class="pmc_sec_title">Conclusions</h2>
<p id="P18">ThermoRawFileParser is an open-source software tool for the conversion of Thermo Raw files into open formats. Because of the growing need for more scalable and distributed computational proteomics approaches, ThermoRawFileParser has been designed to easily plug into large-scale workflow systems such as Galaxy, Nextflow, or OpenMS. The current implementation also provides support for native writing into Amazon web service object stores (S3), making the tool highly portable to cloud architectures. Finally, the modular design of the library, along with its open source nature, allows other researchers to contribute to and extend ThermoRawFileParser for new file formats in the future. Benchmarking tests on gold standard datasets against the ProteoWizard exporter show major improvements in peak detection, and noticeable increases in peptide and protein identifications while maintaining quantitative accuracy.</p></section><section id="SM"><h2 class="pmc_sec_title">Supplementary Material</h2>
