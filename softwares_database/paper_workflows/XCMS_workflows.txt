========== paper_workflow entry 3 ==========
related_tool: XCMS
sample_description: The sample used in the research consists of centroided liquid chromatography/mass spectrometry (LC/MS) data in the open-source .mzML format across N_tot samples in a cohort. Each sample file contains data points x = (rt, m/z, u), where rt is retention time, m/z is mass-to-charge ratio, and u is intensity. An individual peak is defined as a subset of data points from a single sample with nearly identical m/z values (corresponding to the same ion) and intensities forming a bell-shaped profile along the rt axis. Peaks corresponding to the same underlying ion across multiple samples constitute a peak group (or feature), characterized by similar shapes, nearly equal m/z values (with small variations due to machine precision), and non-linear rt drift across samples.
complete_workflow_description: The method employs the mzLearn algorithm—a software tool specifically designed for LC/MS feature detection and alignment—not XCMS. The procedure comprises six sequential stages: (A) Patch creation: Each sample is partitioned into non-overlapping, dynamically resized bounding boxes (patches) enclosing potential peaks; coarse patching uses MZ_coarse = 2 × mz_tol × MZ_max and RT_coarse = RT_max / 5; dynamic resizing adapts patch boundaries using distance thresholds D_rt = μ_drt + 0.1σ_drt and D_mz = μ_dmz + 0.1σ_dmz computed from successive point distances along rt and m/z axes; noisy patches are removed via autocorrelation filtering with an initial threshold Tac(0) = 0.5, refined iteratively to the 5th percentile of per-peak autocorrelation scores after Stage-1 and Stage-2 pin discovery. (B) Cross-sample patch alignment: Reference patch X_p from sample k is cross-correlated with candidate bounding boxes X′ in sample k′, whose rt bounds are initially set to [rt_min + lbd, rt_max + ubd] with lbd = −RT_max/50 and ubd = RT_max/50; rt axes are binned at Δ = μ_drt/10, with intensity averaging for multi-point bins and interpolation (or min-intensity imputation when drt > D_rt) for empty bins; alignment function AL(X_p, X′, d) = w_μd,σd[d] ⋅ (F_ΔX_p ⋆ F_ΔX′)[d] is maximized over rt-displacement d to determine optimal alignment d*, yielding aligned patch-group pairs {X_p^k, X_p^k′}. (C) rt-drift estimation and re-alignment: A learned rt-drift map is constructed to estimate sample-wise rt drift (μ_d) and uncertainty (σ_d); the expected drift function w_μd,σd[d] is updated to be 1 within the 2σ_d neighborhood of μ_d and decay to 0 beyond it, refining the alignment function in subsequent iterations. (D) Peak extraction: Peaks are extracted from aligned correlated-patch groups using shape-aware criteria. (E) Peak group refinement: Candidate peak groups are improved using updated parameters and the refined rt-drift map in an iterative learning loop (three total iterations). (F) Intensity drift correction: An intensity drift map is estimated and applied to normalize feature intensities across samples, correcting for instrument-induced intensity drifts. The final output is a two-dimensional feature table where rows represent features (peak groups) and columns represent normalized intensities across N_p samples.

sample_description: The study utilized MS/MS spectral data from the METLIN tandem mass spectral database, comprising over 960,000 empirically acquired and authenticated chemical standards. Only spectra derived directly from authenticated reference standards were included—no in silico–predicted or library-propagated spectra were used. complete_workflow_description: The method employed a custom computational pipeline implemented in Python v3.11 (pandas v2.2.2, numpy v1.26.4, scipy v1.13.1, scikit-learn v1.4.0) and R v4.3.2 (splines, mgcv, ggplot2), with Jupyter Notebooks used for development and visualization. The workflow consisted of five core steps: (1) Loading centroided METLIN MS/MS spectra acquired at 0, 10, 20, and 40 eV; (2) Fragment tracking across collision energies using ±0.5 Da m/z tolerance and an iterative m/z matching algorithm requiring consistent signal detection across ≥3 of the 4 CEs to group recurring fragment ions; (3) CE–intensity profiling and spline-based CE prediction: for each matched ion group, absolute intensity profiles across CEs were modeled using cubic splines (k = 2, smoothing factor s = 0); the predicted optimal CE was defined as the spline curve maximum, clamped to a minimum of 5 eV; fragments appearing in only one CE or exhibiting nonmonotonic/discontinuous behavior were excluded to eliminate in-source fragments and isotopic interferences; (4) Transition selection: fragments were ranked by relative intensity at their predicted optimal CE; only fragments at least 2.0 Da lower than the precursor m/z (±0.1 Da) were considered; the quantifier ion was selected as the most intense and stable fragment across the CE–intensity profile, while the qualifier ion was the next-highest intensity fragment meeting reproducibility and mass separation criteria (≥2.0 Da from precursor); adduct designations were intentionally omitted to maintain a precursor-centric approach, improving algorithmic stability and cross-class consistency; (5) AI-guided refinement: supervised regression models (RandomForestRegressor and GradientBoostingRegressor from scikit-learn) evaluated empirical vs. spline-predicted CEs to identify optimal spline-fitting conditions per chemical class; large language models (ChatGPT 5, Grok, Gemini) were used interactively for conceptual algorithm development, code refinement, and comparative testing—but all final code, modeling, and analyses were performed exclusively by the authors; AI served solely as an efficiency and model-selection aid, not as a replacement for empirical spline modeling. Large-scale MRM generation was executed on the Garibaldi 64-bit Linux computing cluster (2,848 cores; 250 TB DDN SFA10K storage with IBM GPFS; Torque queue system). Output transitions were formatted as [precursor m/z] → [product m/z] pairs with associated optimized CE values, indexed by METLIN Identification Number (MID), and made publicly accessible via the METLIN web platform (https://metlin.scripps.edu).

complete_workflow_description: G-Aligner is a software tool for LC–MS feature alignment that implements a graph-based combinatorial optimization framework. Input preparation requires users to supply feature tables (csv/tsv format) containing m/z, retention time, and intensity per LC–MS run; raw files (if using profile-based alignment) must be converted to mzML (via MSConvert) or aird (via AirdPro) format. Retention time alignment is performed using two built-in methods: (i) RANSAC (RANdom SAmple Consensus)—a feature-based, iterative, outlier-robust method that fits linear or nonlinear models by selecting random subsets, classifying inliers/outliers based on model consistency, and selecting the model with maximum inliers; default setting uses linear RANSAC due to speed, stability, and no raw file dependency; (ii) OBI-Warp—an open-source Python implementation (first of its kind) of Ordered Bijective Interpolated Warping, which extends dynamic time warping (DTW) to compute optimal bijective warping functions between LC–MS profiles, followed by piecewise cubic Hermite interpolation for smoothness; previously validated in XCMS (OBI-Warp) and MZmine2 (RANSAC). Feature matching proceeds in three stages: (1) Graph building—features across all runs are superimposed in a shared m/z–retention time coordinate system; neighborhoods are searched using user-defined m/z tolerance (Δm/z) and retention time tolerance (ΔRT); an undirected relation graph is constructed where nodes represent features and edges represent potential correspondences; edge weights are computed as weighted sum: (1/3) × (|Δm/z|/m/z_tolerance + |ΔRT|/RT_tolerance + 1 − min(normed_area)/max(normed_area)), where normed_area = feature_intensity / max_intensity_in_component_per_run. (2) Graph splitting—relation graph is decomposed into maximal connected components (each representing candidate analyte groups), treated as independent multipartite subgraphs where nodes from the same run belong to the same partite and edges only connect nodes from different runs. (3) Assignment solving—the feature matching problem is formulated as an unbalanced multidimensional assignment problem (MAP) on each multipartite component: each solution γ contains p matchings (p = max(n₁,…,nₘ)+1), each matching γⱼ is a unique M-partite linkage Lᵢ₁…ᵢₘ = {fᵢ₁¹,…,fᵢₘᴹ} including optional placeholder nodes fₙₖᵏ indicating unmatched runs; constraints ensure node uniqueness, non-overlap of non-placeholder nodes, and full coverage of all features. Matching cost C(γⱼ) comprises: distribution cost (total weight of minimum spanning tree of the subgraph induced by γⱼ), connectivity cost (w_c × N_c, where N_c = number of connected subgraphs in induced subgraph), missing node cost (w_p × N_p, where N_p = number of placeholder nodes), and full-match bonus (−b for fully connected matchings without placeholders); all penalty/bonus parameters (w_c, w_p, b) are pre-optimized and non-adjustable. Three solvers are provided: (i) Gurobi solver—converts MAP to integer linear programming and uses Gurobi optimizer for global optimum; (ii) Greedy solver—iteratively selects minimum-cost matching, marks matched features as unavailable (infinite cost), and builds solution incrementally; (iii) VLSNS solver—variable-length stochastic neighborhood search (details not fully shown in excerpt but implied as a heuristic alternative).
