</div></section></section><section aria-label="Article content"><section class="body main-article-body"><section class="abstract" id="Abs1"><h2>Abstract</h2>
<p id="Par1">Untargeted high-resolution mass spectrometry is a key tool in clinical metabolomics, natural product discovery and exposomics, with compound identification remaining the major bottleneck. Currently, the standard workflow applies spectral library matching against tandem mass spectrometry (MS<sup>2</sup>) fragmentation data. Multi-stage fragmentation (MS<sup>n</sup>) yields more profound insights into substructures, enabling validation of fragmentation pathways; however, the community lacks open MS<sup>n</sup> reference data of diverse natural products and other chemicals. Here we describe MS<sup>n</sup>Lib, a machine learning-ready open resource of &gt;2 million spectra in MS<sup>n</sup> trees of 30,008 unique small molecules, built with a high-throughput data acquisition and processing pipeline in the open-source software mzmine.</p>
<section id="kwd-group1" class="kwd-group"><p><strong>Subject terms:</strong> Metabolomics, Mass spectrometry</p></section></section><section class="abstract" id="Abs2"><hr class="headless">
<p id="Par2">MSnLib is a large-scale, open MS<sup>n</sup> spectral library featuring &gt;2.3 million MS<sup>n</sup> and &gt;357,000 MS<sup>2</sup> spectra for 30,008 unique small molecules.</p></section><section id="Sec1"><h2 class="pmc_sec_title">Main</h2>
<p id="Par3">Accurate structural elucidation and compound annotation in untargeted mass spectrometry (MS) typically rely on matching fragmentation spectra (MS<sup>2−n</sup>) against reference libraries<sup><a href="#CR1" class="usa-link" aria-describedby="CR1">1</a>–<a href="#CR3" class="usa-link" aria-describedby="CR3">3</a></sup>. However, low annotation rates remain a persistent challenge, largely due to the limited structure coverage of high-quality open spectral libraries compared with the vast known chemical space captured in compound databases such as COCONUT<sup><a href="#CR4" class="usa-link" aria-describedby="CR4">4</a></sup>, ChEMBL<sup><a href="#CR5" class="usa-link" aria-describedby="CR5">5</a></sup> or PubChem<sup><a href="#CR6" class="usa-link" aria-describedby="CR6">6</a>,<a href="#CR7" class="usa-link" aria-describedby="CR7">7</a></sup>. Obtaining reference standards, especially purified natural products, is challenging and costly. In multi-stage fragmentation (MS<sup>n</sup>), precursor ions are selected and fragmented in multiple iterations, producing spectral trees with deeper structural insights<sup><a href="#CR8" class="usa-link" aria-describedby="CR8">8</a>–<a href="#CR10" class="usa-link" aria-describedby="CR10">10</a></sup>. While MS<sup>n</sup> provides deeper structural information than MS<sup>2</sup>, and is crucial for characterizing complex molecules and distinguishing isomers<sup><a href="#CR8" class="usa-link" aria-describedby="CR8">8</a>,<a href="#CR9" class="usa-link" aria-describedby="CR9">9</a>,<a href="#CR11" class="usa-link" aria-describedby="CR11">11</a></sup>, its widespread application is constrained by the lack of public data. Open MS<sup>n</sup> (that is, n &gt; 2) spectral entries currently number below 2,000, in contrast to the more than 700,000 MS<sup>2</sup> entries for the more than 30,000 compounds covered in the open libraries GNPS<sup><a href="#CR12" class="usa-link" aria-describedby="CR12">12</a></sup>, MoNA and MassBank EU<sup><a href="#CR13" class="usa-link" aria-describedby="CR13">13</a></sup>. The mzCloud database contains the most extensive MS<sup>n</sup> collection, with more than 16 million spectra for over 30,000 unique compounds (April 2024). Like other proprietary MS libraries, including Wiley, NIST23 and METLIN<sup><a href="#CR14" class="usa-link" aria-describedby="CR14">14</a></sup>, data in mzCloud are locked and cannot be downloaded in open readable formats, thereby limiting their use in other tools and the training of machine learning models.</p>
<p id="Par4">Here we introduce MS<sup>n</sup>Lib, an open large-scale MS<sup>n</sup> library that covers more than 30,000 unique compound structures in over 2.3 million MS<sup>n</sup> spectra, and which significantly expands public MS resources. We describe our scalable, high-throughput pipeline combining collaborative compound sourcing, an open-source metadata curation script, rapid data acquisition, and automated data processing implemented in the open-source software mzmine<sup><a href="#CR15" class="usa-link" aria-describedby="CR15">15</a></sup>. Large-scale spectral library efforts are challenged by limited access to diverse, often costly compound collections. Through a collaborative network, we obtained seven collections totaling 37,829 compounds and 34,413 unique structures, representing a broad chemical space across various natural and synthetic classes (Extended Data Table <a href="#Tab1" class="usa-link">1</a>, Extended Data Fig. <a href="#Fig3" class="usa-link">1</a>, Supplementary Note <a href="#MOESM1" class="usa-link">1</a>, Supplementary Fig. <a href="#MOESM1" class="usa-link">1</a> and Supplementary File <a href="#MOESM4" class="usa-link">1</a>).</p>

<figcaption><p>If a compound (the same InChIKey) is included in multiple compound libraries, it is kept in the smallest one. Most compounds fall into the size range of small molecules with masses below 600 and logP values below 5, following Lipinski’s rule. The compound libraries show differences in their covered compound classes and atomic compositions. Supplementary Fig. <a href="#MOESM1" class="usa-link">1</a> presents additional histograms.</p></figcaption></figure><p id="Par5">Our library generation pipeline consists of three stages: metadata curation, data acquisition, and data processing (Fig. <a href="#Fig1" class="usa-link">1</a>). The main steps include metadata clean-up and acquisition sequence creation (Fig. <a href="#Fig1" class="usa-link">1a</a>), followed by high-throughput data acquisition (Fig. <a href="#Fig1" class="usa-link">1b</a>), and conclude with automated spectral library generation in mzmine (Fig. <a href="#Fig1" class="usa-link">1c</a>). High-quality metadata curation is critical. We developed a Python script to clean input structures (SMILES/InChI), removing salts and applying harmonization steps (Fig. <a href="#Fig1" class="usa-link">1a</a>). This script also enriches compound metadata by querying numerous chemical, biological and drug databases and applying compound classifiers. Finally, unique sample identifiers (IDs) are assigned to aid in later data processing. Task orchestration via the Python-based Prefect framework manages and accelerates database queries (Supplementary Fig. <a href="#MOESM1" class="usa-link">2</a>). More details are given in <a href="#Sec2" class="usa-link">Methods</a> and Supplementary Note <a href="#MOESM1" class="usa-link">2</a>.</p>

<figcaption><p><strong>a</strong>, Metadata clean-up and acquisition sequence generation. The metadata clean-up process consists of structure harmonization, experiment planning, and optional database queries to retrieve general compound, drug, natural product or other information. <strong>b</strong>, Sample preparation and flow injection data-dependent acquisition. DDA, data-dependent acquisition; HRMS, high-resolution mass spectrometry.</p></figcaption></figure><p id="Par6">MS<sup>n</sup> data acquisition is challenging due to the long MS cycle times that are required to acquire deep and wide spectral trees (Extended Data Fig. <a href="#Fig4" class="usa-link">2</a>). In a pilot study (Supplementary Note <a href="#MOESM1" class="usa-link">3</a>), we developed a high-throughput dual-pump flow injection method to capture high-quality MS<sup>n</sup> spectra for multiple adducts of up to 10 compounds per injection (Fig. <a href="#Fig1" class="usa-link">1b</a>). Specifically the automatic gain control, injection time and mass resolution were optimized to raise spectral quality and signal-to-noise ratios (Extended Data Fig. <a href="#Fig5" class="usa-link">3</a> and Supplementary Fig. <a href="#MOESM1" class="usa-link">3</a>). Reproducible static noise signals were identified and later removed during data processing (Supplementary Fig. <a href="#MOESM1" class="usa-link">4</a>). Using the optimized method, all compounds were analyzed in both ionization modes in 23 days and 9,060 injections using auto-generated sequences with unique sample IDs.</p>

<figcaption><p><strong>a</strong>, The noise intensity, here defined by the lowest signal in each MS<sup>3</sup> scan, is influenced by the injection time of the C trap. Internal processing by the instrument vendor normalizes the intensity values by dividing them by the injection time, leading to higher absolute noise levels for shorter injection times. Method 1 (blue): AGC 60%, Resolution 15k; Method 2 (orange): AGC 100%, Resolution 15k; Method 3 (magenta): AGC 100%, Resolution 60k.</p></figcaption></figure><p id="Par7">Addressing the otherwise laborious data processing, we implemented an automated library-building workflow in mzmine (Fig. <a href="#Fig1" class="usa-link">1c</a>). It imports data, builds MS<sup>n</sup> trees and annotates features against curated metadata by searching for compounds as various expected adducts or in-source fragments using their exact <em>m</em>/<em>z</em> ratio. The sample’s known composition constrained annotations. The mzmine feature table facilitates manual validation with annotations and ion traces (Supplementary Fig. <a href="#MOESM1" class="usa-link">5</a>). Key automated quality checks include precursor purity and fragment annotation rates. Finally, spectra were merged on different levels and exported in open MS library formats (<a href="#Sec2" class="usa-link">Methods</a>, Supplementary Note <a href="#MOESM1" class="usa-link">4</a> and Supplementary Fig. <a href="#MOESM1" class="usa-link">6</a>).</p>
<p id="Par8">Application of our automated workflow to the seven compound libraries successfully generated MS<sup>n</sup> trees for 30,008 unique compounds (87% coverage), yielding 357,065 MS<sup>2</sup> and over 2.3 million MS<sup>n</sup> spectra after merging and deduplication (Extended Data Tables <a href="#Tab2" class="usa-link">2</a> and <a href="#Tab3" class="usa-link">3</a>). This establishes MS<sup>n</sup>Lib as a large-scale open library and enables it to significantly expand publicly available MS<sup>n</sup> data. Achieving this high coverage required the combining of both ionization modes, given that many compounds were detected exclusively in positive (&gt;12,200) or negative (&gt;3,400) ionization, alongside those found in both (~14,300) (Fig. <a href="#Fig2" class="usa-link">2a,b</a>, Supplementary File <a href="#MOESM4" class="usa-link">1</a> and Supplementary Figs. <a href="#MOESM1" class="usa-link">7</a>–<a href="#MOESM1" class="usa-link">13</a>). Comparison with existing libraries confirms MS<sup>n</sup>Lib’s complementarity, contributing 22,700 new compounds and valuable MS<sup>n</sup> trees (Fig. <a href="#Fig2" class="usa-link">2c</a>). The unique chemical space covered by MS<sup>n</sup>Lib and projected using the data visualization method, TMAP<sup><a href="#CR16" class="usa-link" aria-describedby="CR16">16</a></sup> (Extended Data Fig. <a href="#Fig6" class="usa-link">4</a>), underscores our method’s capability to substantially expand spectral knowledge. Supplementary Fig. <a href="#MOESM1" class="usa-link">14</a> shows a representative MS<sup>n</sup>Lib entry in mzmine’s MS<sup>n</sup> tree visualizer. Supplementary Note <a href="#MOESM1" class="usa-link">5</a> provides a potential explanation for missed compounds.</p>

<p id="Par21">A Python script (metadata_cleanup_prefect.py) was developed for the curation of metadata. The main purpose of this script is structure extraction, salt removal, and standardization. Structure standardization was based on the ChEMBL structure pipeline Python package<sup><a href="#CR18" class="usa-link" aria-describedby="CR18">18</a></sup>. The complete clean-up failed with the original pipeline for specific structures (when a salt was given without a dot in the structure) and required an additional initial salt removal step and a second clean-up run. The cleaned and standardized structure is used for calculating other structural information such as canonical and, if available, isomeric SMILES (simplified molecular input line entry system), InChI (international chemical identifier developed by the International Union of Pure and Applied Chemistry), InChIKey (a condensed version of InChI), logP (the logarithm of the octanol–water partition coefficient) and monoisotopic mass. This mass is used during the automatic library generation. Optionally, additional information, such as whether a compound is considered a natural product or used as a drug, can be gathered from other databases based on a name, database identifier or structure search in PubChem, ChEMBL or other public resources (Supplementary Note <a href="#MOESM1" class="usa-link">2</a>). Queries can be easily turned off or implemented in the Python code. In our code, all databases that require a local file are deactivated by default.</p></section><section id="Sec6"><h3 class="pmc_sec_title">Sequence generation</h3>
<p id="Par22">An additional Python script (sequence_creation.py) was used to prepare the sequence table based on plate and well information. The sequence for each plate is built so that it is first analyzed in positive ion mode, followed by negative ionization. A file name is generated automatically and contains the date, a unique sample identifier (combination of library, plate number and well location), the method used, and the polarity. The unique sample identifier is important because it is used for the automatic annotation and extraction of the acquired spectral data. Therefore, the unique sample identifier in the metadata column needs to be matched with a substring of the acquisition file name. Here, only this identifier is important in the name, enabling the addition of other prefixes and suffixes, for example, the date, polarity or method. The script generates acquisition sequence files specific to the Xcalibur sequence layout using the flow injection–Orbitrap MS<sup>n</sup> method. This can be easily modified for other analysis platforms, depending on their layout.</p></section><section id="Sec7"><h3 class="pmc_sec_title">Sample preparation</h3>
<p id="Par23">Our mass spectral library contains seven different compound libraries. The MCEBIO library was prepared with an OT-2 liquid handler (Opentrons Labwork) to pool and dilute 10 compounds in each well of three 384-well plates, resulting in a concentration of 20 µM for each compound in a mixture of methanol and water (1:1). For the MCESCAF, MCEDRUG, OTAVAPEP, ENAMMOL and ENAMDISC libraries, the Echo 650 Liquid Handler (Beckmann Coulter) was used to pool eight compounds in 384-well plates, and a CERTUS FLEX liquid dispenser (Fritz Gyger AG) diluted the samples with 80–90 µl methanol and water (mixed in a 1:1 ratio), resulting in a concentration between 8 and 12 µM. The NIHNP library was further processed at the University of California San Diego, California, USA. Up to seven compounds were pooled in 96-well plates, resulting in a concentration of 5 µM. Because the plates showed strong evaporation, they were refilled with 50–100 µl methanol, acetonitrile and water (mixed in a 4:4:2 ratio), which was the previous mixture. Therefore, the end concentration is unknown.</p></section><section id="Sec8"><h3 class="pmc_sec_title">Data acquisition</h3>
<p id="Par24">The flow injection–MS<sup>n</sup> analysis was performed using a Vanquish Horizon UHPLC system with two pumps coupled to an Orbitrap ID-X (Thermo Fisher Scientific) instrument. The instrument was calibrated in positive and negative ion mode with the Pierce FlexMix calibration solution prior to a library batch. Different set-ups were tested to extend the peak width for more MS<sup>n</sup> experiments, to reach the mass analyzer quickly, and to avoid sample carryover. Two pumps were connected with a T-piece. The first pump, that is, the delivery pump, ran through the autosampler. The flow for this pump was initially set to 45 µl min<sup>−1</sup> for the injection to reach the T connection quickly. After 0.27 min the flow was decreased to 5 µl min<sup>−1</sup> and kept constant until 1.35 min. Over the next 0.15 min the flow was increased to 45 µl min<sup>−1</sup> and kept constant for another 1.5 min to clean the sample lines and to avoid sample carryover. The second pump, that is, the make-up pump, was used to broaden the elution profile. To maintain a combined constant flow of 55 µl min<sup>−1</sup>, the make-up pump started at 10 µl min<sup>−1</sup>, was increased to 50 µl min<sup>−1</sup> after 0.27 min, and kept at that rate until 1.35 min. The flow was gradually decreased back to 10 µl min<sup>−1</sup> over the next 0.15 min and kept constant for another 1.5 min. The whole run time per injection was 3 min. Both pumps used an isocratic mixture of water and acetonitrile at a 50:50 ratio, both with 0.1% formic acid. The switching of the flow speed is important for cleaning because the delivery pump runs at a low flow rate of 5 µl min<sup>−1</sup> during most of the time of the sample delivery. It must be noted that the method can also be used with a second pump running constantly at 50 µl min<sup>−1</sup>, resulting in an altered flow rate of up to 95 µl min<sup>−1</sup> during the analysis but with no big changes during the data acquisition.</p>
<p id="Par25">The injection volume was set to 2 µl, except for that for the NIHNP library, which was set to 3 µl due to the lower concentration. H-ESI was used for ionization with a vaporizer temperature of 75 °C and ion transfer tube temperature of 275 °C. The voltages were set to 3,000 V and 2,000 V for positive and negative ionization modes, respectively. The sheath gas was set to 25 a.u. and the auxiliary gas was set to 5 a.u. No sweep gas was used. The MS<sup>n</sup> tree was built with the following main settings, with the Orbitrap as the mass analyzer: For MS<sup>1</sup>, data were analyzed from <em>m</em>/<em>z</em> 115 to 2,000 with a resolution of 30,000, a radiofrequency (RF) lens of 50%, an automatic gain control (AGC) target of 100% (40,000 a.u.), and a maximum injection time (maxIT) of 50 ms. After one MS<sup>1</sup> scan, the three most intense ions, with a minimum intensity of 6 × 10<sup>5</sup> a.u. in positive and 2 × 10<sup>5</sup> a.u. in negative ionization, were picked using data-dependent acquisition with an isolation window of <em>m</em>/<em>z</em> 1.2, a resolution of 15,000, an AGC target of 30% (1.2 × 10<sup>4</sup> a.u.), and maxIT of 50 ms for positive and 80 ms for negative ion mode. Three fragmentation experiments to cover different collision energies (a maximum of nine scans) were conducted. For MS<sup>2</sup>, the energies were set to 20 eV and 60 eV, and the assisted collision energy to achieve the optimal MS<sup>2</sup> energy for further MS<sup>n</sup> stages was tested in 15 eV steps, starting at 15 eV, and increasing to 30 eV, 45 eV, 60 eV and 75 eV. From this assisted collision energy step, the top five signals, with a minimum intensity of 2 × 10<sup>4</sup> a.u. in positive ion mode and 1 × 10<sup>4</sup> a.u. in negative ion mode, and within the mass range of <em>m</em>/<em>z</em> 90–2,000, were isolated for MS<sup>3</sup> with an MS<sup>1</sup> isolation window of <em>m</em>/<em>z</em> 1.2 and an MS<sup>2</sup> isolation window of 2. The resolution was set to 60,000, the AGC target to 100% (5 × 10<sup>4</sup>), and the maxIT to 200 ms for the positive and 500 ms for the negative ion mode. Three fixed collision energies of 20 eV, 40 eV and 60 eV were applied, resulting in a maximum number of 15 scans. The two most intense signals with a minimum intensity of 2 × 10<sup>4</sup> a.u. in positive and 1 × 10<sup>4</sup> in negative ion mode were selected from the 40 eV MS<sup>3</sup> scans for the MS<sup>4</sup> experiments, with an isolation window of <em>m</em>/<em>z</em> 2.2. All other settings were used as in MS<sup>3</sup>. For MS<sup>5</sup>, the two highest signals of an 40 eV MS<sup>4</sup> scan and within a mass range of 150–2,000 were further fragmented using an isolation window of <em>m</em>/<em>z</em> 3 and the same settings as MS<sup>3</sup> and MS<sup>4</sup>. Only 40 eV and 60 eV were used as the collision energy settings, given that 20 eV produced mainly the precursor ion. Dynamic exclusion was carried out at every MS<sup>n</sup> stage, meaning that each precursor was selected three times within 200 s and was excluded for the following 70 s with a mass tolerance of <em>m</em>/<em>z</em> 0.2. Additionally, isotopes of selected precursor ions were excluded within a window of <em>m</em>/<em>z</em> 2 for unassigned isotopes. It must be noted that the maximum occurrence should be set to a number divisible by 3 to carry out experiments for all three collision energies. Before the standard analysis, multiple blank injections were analyzed, and the detected signals were added to a targeted mass exclusion list. This exclusion list was updated after running 10 sample injections and the detection of reoccurring signals in all samples. The MS<sup>n</sup> schema is presented in Extended Data Fig. <a href="#Fig4" class="usa-link">2</a> and for one example compound in Supplementary Fig. <a href="#MOESM1" class="usa-link">14</a>. The processing was done in mzmine. A full batch configuration file is supplied as Supplementary File <a href="#MOESM5" class="usa-link">2</a> (mzmine_exclusion_blankprofile_pos.mzbatch) and Supplementary File <a href="#MOESM6" class="usa-link">3</a> (mzmine_exclusion_blankprofile_neg.mzbatch). Our system showed higher background signals in empty scans or less rich fragmentation scans around <em>m</em>/<em>z</em> 149.72 and <em>m</em>/<em>z</em> 173.52, therefore, these were added to an exclusion list with a width of <em>m</em>/<em>z</em> 0.03 for all MS<sup>n</sup> levels. The fragmentation tree is presented in Extended Data Fig. <a href="#Fig7" class="usa-link">5</a> with an example given in Supplementary Fig. <a href="#MOESM1" class="usa-link">14</a>. All settings are listed in Supplementary Tables <a href="#MOESM1" class="usa-link">1</a> and <a href="#MOESM1" class="usa-link">2</a>.</p></section><section id="Sec9"><h3 class="pmc_sec_title">Automatic MS<sup>n</sup> tree library generation and data evaluation in mzmine</h3>

<p id="Par48">The newly generated spectral library in positive ion mode for the MCEBIO library was imported into mzmine and reprocessed to a feature list. Only MS<sup>2</sup> and pseudo-MS<sup>2</sup> spectra were used, resulting in 48,069 spectra, to reduce data complexity, and given that most tools are limited to use with MS<sup>2</sup> spectra. The feature list annotation was exported as a .csv file retaining the original information, for example, compound name and adduct for later comparison. Furthermore, the list was exported with the mzmine module named molecular networking files in an .mgf data format, compatible with running feature-based molecular networking (FBMN) utilizing the Global Natural Products Social Molecular Networking (GNPS) infrastructure. The parameters for FBMN were set to precursor ion and fragment ion mass tolerances of 0.02 Da, a minimum pairs cosine value (min. pairs cos.) of 0.7 (minimum cosine score necessary to connect to experimental MS<sup>2</sup> spectra), a network TopK value of 1,000, a minimum number of matched fragment ions of 4, maximum connected component size of 0, and a maximum shift between precursors of 500 Da.</p>
<p id="Par49">For matching our library against the three most commonly used public spectral databases, we used LC–MS/MS spectra from the MassBank of North America (MoNA, <a href="https://mona.fiehnlab.ucdavis.edu/downloads" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://mona.fiehnlab.ucdavis.edu/downloads,.json</a>, accessed 8 December 2023), spectra from the MassBank EU database, specifically MassBank_NIST.msp (<a href="https://github.com/MassBank/MassBank-data/releases/tag/2023.11" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/MassBank/MassBank-data/releases/tag/2023.11</a>), and spectra from the GNPS library, namely ALL_GNPS_NO_PROPOGATED (<a href="https://gnps-external.ucsd.edu/gnpslibrary" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://gnps-external.ucsd.edu/gnpslibrary</a>, accessed 8 December 2023). Prior to matching our MS<sup>n</sup>Lib’s feature list against these public spectral databases (see the first step), the original annotations were removed to retain only spectral library matches. We used the following settings: a minimum matched signals setting of 4, a precursor <em>m</em>/<em>z</em> tolerance and spectral <em>m</em>/<em>z</em> tolerance of 0.005 or 10 ppm, removing the precursor, a weighted cosine similarity with a minimum similarity of 0.6, and the weighting of the square root of the signal intensity (<em>m</em>/<em>z</em><sup>0</sup> × I<sup>0.5</sup>). The top five and top 10 matches were exported for further evaluation. Here, the feature ID produced by mzmine was used to compare the annotations by spectral matching with the original compound information. The structures of the matched compounds were cleaned with the same script as in the metadata clean-up and a new InChIKey string was computed. This InChIKey string was used to find spectra that were matched to the identical compound. Finally, to further evaluate the top 10 matching hits, we calculated their Tanimoto similarity, based on Morgan fingerprints (radius = 2, nBits = 2048), and determined their maximum common edge subgraph (MCES)<sup><a href="#CR19" class="usa-link" aria-describedby="CR19">19</a></sup>, using the default settings in the Python package. The FBMN visualization is provided in Supplementary File <a href="#MOESM10" class="usa-link">7</a>.</p></section><section id="Sec12"><h3 class="pmc_sec_title">Reporting summary</h3>

The mass spectral libraries included in MS<sup>n</sup>Lib were deposited as .mgf and .json files in the Zenodo dataset <a href="https://doi.org/10.5281/zenodo.11163380" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">11163380</a> under the <a href="https://creativecommons.org/licenses/by/4.0/" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">CC BY 4.0</a> license. Here, each spectral library for the individual compound libraries is uploaded as MS<sup>2</sup> only or the full MS<sup>n</sup> library. The MS<sup>2</sup> libraries contain the best and merged spectra for all acquired MS<sup>2</sup> spectra, including the pseudo-MS<sup>2</sup>, in which the whole fragmentation tree is combined into a single spectrum. Polarities are kept separated, resulting in four entries for each compound library and library format. Additionally, the MS<sup>2</sup> data are uploaded as a reference library in GNPS (<a href="https://external.gnps2.org/gnpslibrary" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://external.gnps2.org/gnpslibrary</a>) in the form of a default gold-level library named MSNLIB-POSITIVE and MSNLIB-NEGATIVE. We recommend using the Zenodo libraries because they contain more metadata and link back to the original data by universal spectrum identifier (USI). Regarding the metadata clean-up, the DrugBank lookup is an optional step, and the data are accessible on request. More information is available on the project website (<a href="https://go.drugbank.com/" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://go.drugbank.com</a>). DrugCentral lookup is an optional step, and their whole database can be downloaded as a PostgreSQL dump from the company’s website (<a href="https://drugcentral.org/" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://drugcentral.org</a>). LOTUS lookup is an optional step, and the whole LOTUS dataset is incorporated into WIKIDATA. The metadata clean-up script contains a Prefect flow to download all relationships from WIKIDATA. Simply run the prepare_wikidata_lotus_data_prefect.py script (<a href="https://github.com/corinnabrungs/msn_tree_library" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/corinnabrungs/msn_tree_library</a>). Broad Institute lookup is an optional step. The drug information can be downloaded as a .txt file from the institute’s website (<a href="https://repo-hub.broadinstitute.org/repurposing" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://repo-hub.broadinstitute.org/repurposing</a>). The FBMN result can be accessed on GNPS: <a href="https://gnps.ucsd.edu/ProteoSAFe/status.jsp?task=c05d34fb31ab4ee99293e722fb7eb83d" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://gnps.ucsd.edu/ProteoSAFe/status.jsp?task=c05d34fb31ab4ee99293e722fb7eb83d</a> Experimental public libraries were downloaded from the corresponding webpages: GNPS, ALL_GNPS_NO_PROPAGATED (<a href="https://external.gnps2.org/gnpslibrary" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://external.gnps2.org/gnpslibrary</a>, accessed 8 December 2023); MassBank EU, MASSBANK_NIST (<a href="https://github.com/MassBank/MassBank-data/releases/tag/2023.11" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/MassBank/MassBank-data/releases/tag/2023.11</a>, accessed 8 December 2023); MassBank North America, LC–MS/MS spectra (<a href="https://mona.fiehnlab.ucdavis.edu/downloads" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://mona.fiehnlab.ucdavis.edu/downloads</a>, accessed 8 December 2023). The dataset used for the library evaluation can be found in MassIVE under <a href="https://massive.ucsd.edu/ProteoSAFe/QueryMSV?id=MSV000096589" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">MSV000096589</a>. Here we used only a subset of group 1 (group1_B*.mzML) for the analysis. The mzmine batch file is supplied as Supplementary File <a href="#MOESM12" class="usa-link">9</a> and the results of this evaluation as Supplementary Files <a href="#MOESM13" class="usa-link">10</a> and <a href="#MOESM14" class="usa-link">11</a>.</p>
<p>The metadata clean-up pipeline was implemented in Python 3.10, with the Prefect library as the task orchestration tool. The source code is available on GitHub under the free and open MIT license (<a href="https://github.com/corinnabrungs/msn_tree_library" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/corinnabrungs/msn_tree_library</a>). The TMAP projections and other analysis are available as Jupyter notebooks on GitHub (<a href="https://github.com/corinnabrungs/msn_tree_library/tree/master/notebooks" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/corinnabrungs/msn_tree_library/tree/master/notebooks</a>). The mzmine code and documentation are available on GitHub under the same license (<a href="https://github.com/mzmine/mzmine3" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/mzmine/mzmine3</a>, <a href="https://github.com/mzmine/mzmine_documentation" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/mzmine/mzmine_documentation</a>).</p></section></section></section><footer class="p courtesy-note font-secondary font-sm text-center"><hr class="headless">
