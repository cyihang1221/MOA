<section id="sec1"><h3 class="pmc_sec_title">Background</h3>
<p id="Par1">Network generation tools coupled with chemical reaction rules have been mainly developed for synthesis planning and more recently for metabolic engineering. Using the same core algorithm, these tools apply a set of rules to a source set of compounds, stopping when a sink set of compounds has been produced. When using the appropriate sink, source and rules, this core algorithm can be used for a variety of applications beyond those it has been developed for.</p></section><section id="sec2"><h3 class="pmc_sec_title">Results</h3>
<p id="Par2">Here, we showcase the use of the open source workflow RetroPath2.0. First, we mathematically prove that we can generate all structural isomers of a molecule using a reduced set of reaction rules. We then use this enumeration strategy to screen the chemical space around a set of monomers and predict their glass transition temperatures, as well as around aminoglycosides to search structures maximizing antibacterial activity. We also perform a screening around aminoglycosides with enzymatic reaction rules to ensure biosynthetic accessibility. We finally use our workflow on an <em>E. coli</em> model to complete <em>E. coli</em> metabolome, with novel molecules generated using promiscuous enzymatic reaction rules. These novel molecules are searched on the MS spectra of an <em>E. coli</em> cell lysate interfacing our workflow with OpenMS through the KNIME Analytics Platform.</p></section><section id="sec3"><h3 class="pmc_sec_title">Conclusion</h3>
<p id="Par3">We provide an easy to use and modify, modular, and open-source workflow. We demonstrate its versatility through a variety of use cases including molecular structure enumeration, virtual screening in the chemical space, and metabolome completion. Because it is open source and freely available on MyExperiment.org, workflow community contributions should likely expand further the features of the tool, even beyond the use cases presented in the paper.</p></section><section id="sec4"><h3 class="pmc_sec_title">Electronic supplementary material</h3>
<p>The online version of this article (10.1186/s13321-017-0252-9) contains supplementary material, which is available to authorized users.</p></section><section id="kwd-group1" lang="en" class="kwd-group"><p><strong>Keywords:</strong> Scientific workflows, Chemical space, Reaction networks generation, Retrosynthesis, Reaction rules, Isomer enumeration</p></section></section><section id="Sec1"><h2 class="pmc_sec_title">Background</h2>
<p id="Par4">The number of known chemical reactions is huge, at the time this manuscript was written there were ~84 million single- and multi-step reactions in the Chemical Abstract Service database (CAS) [<a href="#CR1" class="usa-link" aria-describedby="CR1">1</a>]. Yet, many reactions in CAS are redundant because the same reactions are applied to different reactants. Identifying identical reactions can be performed by computing reaction rules. Reaction rules represent reactions at the reaction center only. In other words, a reaction rule comprises only the substructures of the reactants and the products for which the atoms are either directly involved in bond rearrangements or are deemed to be essential for the reactivity of the reaction center. While a set of reaction rules is of course not available for all known chemical reactions, rules have been compiled for focused applications, such as retrosynthesis planning [<a href="#CR2" class="usa-link" aria-describedby="CR2">2</a>, <a href="#CR3" class="usa-link" aria-describedby="CR3">3</a>], the discovery of novel chemical entities in medicinal chemistry [<a href="#CR4" class="usa-link" aria-describedby="CR4">4</a>], xenobiotic (including drug) degradation [<a href="#CR5" class="usa-link" aria-describedby="CR5">5</a>], metabolomics [<a href="#CR6" class="usa-link" aria-describedby="CR6">6</a>], and metabolic engineering [<a href="#CR7" class="usa-link" aria-describedby="CR7">7</a>–<a href="#CR10" class="usa-link" aria-describedby="CR10">10</a>]. Depending on the application, the number of rules varies from less than one hundred to few thousands, but in all cases the number of known reactions per application far exceeds the number of rules (there are for instance more than 14,000 reactions in metabolic databases such as MetaNetX [<a href="#CR11" class="usa-link" aria-describedby="CR11">11</a>]). There are several ways of coding reaction rules (for instance, BE-matrices [<a href="#CR12" class="usa-link" aria-describedby="CR12">12</a>] and fingerprints [<a href="#CR13" class="usa-link" aria-describedby="CR13">13</a>]) but most of the time the rules can be represented by reaction SMARTS [<a href="#CR14" class="usa-link" aria-describedby="CR14">14</a>], as it is done in the current paper.</p>
<p id="Par5">The purpose of reactions rules is to generate reaction networks. The rules can be used in a forward manner to find for instance the metabolic degradation products of a drug, or in a reverse manner to find the reactions producing a desired product from a set of available reactants. In this later usage one produces retrosynthesis reaction networks. Several tools have been developed in the past to generate (retrosynthesis) reaction networks and reviews are available for synthesis planning [<a href="#CR2" class="usa-link" aria-describedby="CR2">2</a>, <a href="#CR3" class="usa-link" aria-describedby="CR3">3</a>] and for metabolic engineering [<a href="#CR15" class="usa-link" aria-describedby="CR15">15</a>]. Disregarding if the rules are applied in a forward or reverse manner, network generation tools are making use of the same core algorithm. Starting from a source set of compounds the core algorithm applies the rules in an iterative fashion either a predefined number of times or until a sink set of compounds has been produced. At each iteration, the algorithm fires the rules on the source set producing <em>new</em> molecular structures and determines the <em>new</em> source set of molecules the rules will be fired upon at the next iteration. That set must comprise molecules that have not been processed before. Further details on the core algorithm and the differences between the various implementations are provided in Faulon et al. [<a href="#CR16" class="usa-link" aria-describedby="CR16">16</a>] and Delépine et al. [<a href="#CR17" class="usa-link" aria-describedby="CR17">17</a>]. In the current paper we make use of an open source workflow (RetroPath2.0 [<a href="#CR17" class="usa-link" aria-describedby="CR17">17</a>]), which follows the above core algorithm. This workflow is not based on original codes but instead was constructed entirely by assembling KNIME nodes [<a href="#CR18" class="usa-link" aria-describedby="CR18">18</a>] developed by the cheminformatics community (primarily RDKit nodes [<a href="#CR19" class="usa-link" aria-describedby="CR19">19</a>]). RetroPath2.0 is the first open source release of a retrosynthesis reaction network generation, and its usage in the current paper beyond network generation demonstrates its versatility. </p>
<blockquote class="text-italic"><p id="Par6">As already mentioned, reaction network generation tools coupled with reactions rules have been developed and used primarily for synthesis planning and metabolic engineering, but can they be used to enumerate molecules (isomers for instance) and more generally to search chemical structures in the chemical space?</p></blockquote>
<p> In principle yes if one can devise reaction rules enabling the production of any molecule in the chemical space. Such a set of rules necessarily exists for all known molecules (such as those in the CAS database) since they have been produced through either natural or synthetic chemical reactions. In practice and as already stated, reaction rules so far developed are application limited. Yet, within their respective application fields, specific rules have been used to discover novel molecules and reaction pathways. Taking experimentally validated examples, the rules associated with the ligand-based de novo design software DOGS (inSili.com LLC) [<a href="#CR4" class="usa-link" aria-describedby="CR4">4</a>] have enabled the production of new chemical entities inhibitors of DAPK3 (death-associated protein kinase 3) [<a href="#CR20" class="usa-link" aria-describedby="CR20">20</a>], metabolic rules for promiscuous enzymes have allowed the discovery of novel metabolites in <em>E. coli</em> [<a href="#CR21" class="usa-link" aria-describedby="CR21">21</a>] and have also been used to engineer metabolic pathways producing 1,4-butanediol [<a href="#CR9" class="usa-link" aria-describedby="CR9">9</a>] and flavonoids [<a href="#CR22" class="usa-link" aria-describedby="CR22">22</a>].</p>
<p id="Par7">Going beyond application limited reaction rules, the main contribution of the present paper is to propose a set of transformation rules that enables the generation of any isomer of any given molecule of the chemical space. Precisely, we prove the claim that any isomer of any given molecule of <em>N</em> atoms, can be reached applying at most O(<em>N</em>
<sup>2</sup>) rules.</p>
<p id="Par8">As illustrations, our transformation rules are used to screen the chemical space for structures that are similar to a given set of well-known monomers and to search aminoglycosides structures maximizing antibacterial activities. The compounds produced by our rules are not necessarily chemically accessible, since our transformation rules are not constructed based on chemical synthesis schema. To probe the (bio)synthetic accessibility of our solutions, we also perform search in the (bio)chemical space using enzymatic reaction rules. The enzymatic rules are also used to propose novel molecules completing <em>E. coli</em> metabolic network and for which masses are found in cell lysate mass spectra.</p>
<p id="Par9">All results presented in this paper have been produced making use of the open source workflow RetroPath2.0. RetroPath2.0 and the associated data are provided as Additional file <a href="#MOESM1" class="usa-link">1</a> and can be downloaded at MyExperiment.org. The only differences between the various usages we have made of the RetroPath2.0 are within (1) the set of reaction rules and (2) the way molecules are selected at each iteration during the network generation process.</p></section><section id="Sec2"><h2 class="pmc_sec_title">Results and discussions</h2>
<p id="Par10">The purpose of this section is to showcase the versatility of RetroPath2.0 by taking use cases of interest to the community. We first propose reaction rules to enumerate isomers (“<a href="#Sec3" class="usa-link">Isomer enumeration</a>” section), we then use the rules to screen in the chemical space structures that are similar to some known monomers (“<a href="#Sec6" class="usa-link">Virtual screening in the chemical space</a>” section) and compute property distribution (Glass transition temperature) in both the Chemical Space and PubChem, we next use a QSAR to search aminoglycosides types molecules for which antibacterial activity is maximized using both isomer transformation rules and enzymatic rules (“<a href="#Sec7" class="usa-link">Search for molecules maximizing biological activities</a>”), and we finally use enzymatic rules to find novel metabolites in <em>E. coli</em> and annotate the MS spectra of an <em>E. coli</em> cell lysate interfacing RetroPath2.0 with OpenMS [<a href="#CR23" class="usa-link" aria-describedby="CR23">23</a>] (“<a href="#Sec8" class="usa-link">Metabolome completion and metabolomics</a>” section).</p>
<section id="Sec3"><h3 class="pmc_sec_title">Isomer enumeration</h3>
<p id="Par11">Isomer enumeration is a long-standing problem that is still under scrutiny [<a href="#CR24" class="usa-link" aria-describedby="CR24">24</a>, <a href="#CR25" class="usa-link" aria-describedby="CR25">25</a>]. Our intent here is not to provide the fastest enumeration algorithm but to demonstrate how RetroPath2.0 can perform that job once appropriate reaction rules are provided. However, we provide in Additional file <a href="#MOESM2" class="usa-link">2</a>: Figure S1 a comparison of Retropath2.0’s execution time with the OMG and PMG software tools [<a href="#CR25" class="usa-link" aria-describedby="CR25">25</a>, <a href="#CR26" class="usa-link" aria-describedby="CR26">26</a>] specifically dedicated to isomers enumeration. Retropath2.0 is found faster than OMG but slower than PMG. Thereafter, we outline two approaches making use of RetroPath2.0. The first is based on the classical <em>canonical augmentation</em> algorithm [<a href="#CR27" class="usa-link" aria-describedby="CR27">27</a>] and the second consists of iteratively transforming a given molecule such that all its isomers are produced. We name this latter approach <em>isomer transformation</em>. In both cases we limit ourselves to structural (constitutional) isomers, as there already exist workflows to enumerate stereoisomers [<a href="#CR28" class="usa-link" aria-describedby="CR28">28</a>] (Additional file <a href="#MOESM2" class="usa-link">2</a>: Figure S2).</p>
<section id="Sec4"><h4 class="pmc_sec_title">Canonical augmentation</h4>
<p id="Par12">The principle of canonical augmentation, which is an orderly enumeration algorithm, is to grow a molecular graph by adding one atom at a time and retaining only canonical graphs for the next iteration [<a href="#CR27" class="usa-link" aria-describedby="CR27">27</a>]. The algorithm first proposed by Brendan McKay has been used to generate the GDB-17 database of small molecules [<a href="#CR29" class="usa-link" aria-describedby="CR29">29</a>]. The original algorithm has also been modified such that at each step a bond (not an atom) is added to the growing molecules [<a href="#CR25" class="usa-link" aria-describedby="CR25">25</a>]. In the present implementation we use the original McKay algorithm [<a href="#CR27" class="usa-link" aria-describedby="CR27">27</a>], consequently, the number of iterations is the number of atoms one wishes the molecule to have. The algorithm can easily be implemented into RetroPath2.0 by choosing as a source set a single unbonded atom, and a rule set depicting all possible ways an atom can be added to a molecular graph (see “<a href="#Sec10" class="usa-link">Methods</a>” section for more information). Considering that an atom can be added to a growing molecule through one, two, or more bonds (depending on its valence), the set of reaction rules is straightforward however cumbersome if one starts to consider all possible atoms types. For this reason we limit ourselves to carbon skeleton as it is usually done in the first step of isomer enumeration algorithm. Figure <a href="#Fig1" class="usa-link">1</a> below depicts the set of rules that generate all triangle free carbon skeletons.

<p id="Par14">The isomer canonical augmentation algorithm becomes more complex when one starts to consider different atom and bond types. To overcome these difficulties the idea of the transformation enumeration approach is to start with one fully-grown molecule to which one applies all possible transformations such that all the structural isomers of the initial molecule are generated. This approach can be implemented in RetroPath2.0 using a hydrogen saturated molecule as a source and a reaction rule set enabling to transform the molecule while keeping the correct valence for each atom. Because atom valences are maintained the total number of bonds must remain the same after the transformations have taken place. In order to maintain the number of bonds constant, for any reaction rule the number of bonds created must equal the number of bonds deleted.</p>
<p id="Par15">RetroPath2.0 applies a reaction rule to a given molecule by first searching all occurrences in the molecule of the subgraph representing the reactant (left side of the rule). To this end the labels on the subgraph are removed. Then for each occurrence of the unlabeled subgraph in the molecule, the labels are restored and the bonding patterns on the molecule are changed accordingly. <p id="Par25">Condition 1 is not respected when a<sub>23</sub> = 2 and a<sub>14</sub> = 0 or 1 or when a<sub>23</sub> = 1 and a<sub>14</sub> = 0, without constraints on a<sub>12</sub> and a<sub>34</sub>: (2 + 1) * 9 = 27 solutions. For the same reason, 27 solutions do not respect condition 2. The solutions that do not respect both Conditions 1 and 2 are (2 + 1) * (2 + 1) = 9. By symmetry arguments, we therefore reduced the solution space from 81 to 81 − 27 − 27 + 9 = 36. These 36 reaction rules are presented in Fig. <a href="#Fig4" class="usa-link">4</a>.
</p>
<figure class="fig xbox font-sm" id="Fig4"><h6 class="obj_head">Fig. 4.</h6>

<figcaption><p>Rules before solution space reduction due to valence and structure considerations. Reactions in green move bonds around without creating or deleting cycles. Reactions in blue change bond order by creating or deleting at least one cycle. Reactions in purple were deleted because valence is limited to 4, and reactions in black were deleted because there cannot be two double bonds on the same atom in a 3 or 4 membered ring</p></figcaption></figure><p id="Par26">We can further reduce the solution space by considering that the maximum atom valence is 4. The solutions that do not respect this constraint are such that a<sub>12</sub> + a<sub>14</sub> = 5, so a<sub>12</sub> = 3 and a<sub>14</sub> = 2 (and this automatically verifies Conditions 1 and 2). Since there are no constraints on a<sub>23</sub> and a<sub>34</sub>, we have 9 such solutions: the solution space has been reduced to 36 − 9 = 27 reactions.</p>
<p id="Par27">One more constraint, imposed by 3D conformation of the molecule, is that there cannot be two double bonds on the same atom in a 3 or 4 membered ring.</p>
<p id="Par28">This must be true for our initial molecule as well as for the produced molecule. For the initial molecule (as can be seen in the 4 black rules under rule 13 in Fig. <a href="#Fig4" class="usa-link">4</a>), when a<sub>12</sub> = a<sub>14</sub> = 2, since a<sub>34</sub> &gt; 1 (bond whose order will be reduced), there is a cycle if a<sub>23</sub> ≠ 0. There are therefore 4 solutions where the initial molecule is invalid: when a<sub>12</sub> = a<sub>14</sub> = 2, and a<sub>34</sub> is 1 or 2 (smaller than a<sub>12</sub>) and a<sub>23</sub> is 1 or 2.</p>
<p id="Par29">This must also be true for the produced molecule. Two double bonds will be produced around atom 1 with a<sub>12</sub> = 3 and a<sub>14</sub> = 1 (this can be seen in the 4 black rules under rule 18 in Fig. <a href="#Fig4" class="usa-link">4</a>). There will be a cycle if a<sub>34</sub> ≠ 1. There are therefore 4 solutions where the produced molecule is invalid: when a<sub>12</sub> = 3, a<sub>14</sub> = 1, and a<sub>34</sub> is 2 or 3 and a<sub>23</sub> is 0 or 1 (smaller than a<sub>14</sub>).</p>
<p id="Par30">Since these solutions respect valence constraints and problem symmetry, they are not included in the previous solution space reductions and therefore the solution space is reduced to 27 − 8 = 19 solutions. A summary table of solution space reduction is given in Additional file <a href="#MOESM3" class="usa-link">3</a>: Table S1. Since we have found 19 different working solutions for all the cases we have left, we have proved that the minimal number of bonds one can change is 4 and the 19 rules described in Fig. <a href="#Fig3" class="usa-link">3</a> generate all these minimal transformations.</p></section><section id="FPar4"><h5 class="pmc_sec_title"><strong>Lemma 2</strong></h5>
<p id="Par31">
<em>Let us consider M</em>
<sub><em>b</em></sub>
<em>an isomer of M</em>
<sub><em>a</em></sub>
<em>. We can apply a rule from this set of</em> 19 <em>rules that will reduce the sum of absolute order differences between those two molecules by at least</em> 2 <em>and at most</em> 4.</p></section><section id="FPar5"><h5 class="pmc_sec_title"><em>Proof</em></h5>
<p id="Par32">Let (a<sub>ij</sub>) be the order of bonds in M<sub>a</sub>, (b<sub>ij</sub>), j Є [2, <em>N</em>], i Є [1, j − 1], the order of bonds in M<sub>b</sub>, where <em>N</em> is the number of atoms in M<sub>a</sub> and M<sub>b</sub>. Since M<sub>b</sub> is different from M<sub>a</sub>, we can find i,j such that a<sub>ij</sub> &gt; b<sub>ij</sub>. By valence conservation in atom A<sub>j</sub>, we can find k such that a<sub>jk</sub> &lt; b<sub>jk</sub>, and by valence conservation of atom A<sub>k</sub>, we can also find l such that a<sub>kl</sub> &gt; b<sub>kl</sub>. Therefore, we are considering 4 atoms and 4 bonds between those atoms, with at least 3 of their orders changing by 1. According to Lemma 1 the minimal number of bonds one can change is 4, so we will also have to change the bond order between A<sub>i</sub> and A<sub>l</sub>. We are therefore considering a minimal transformation, so we know thanks to Lemma 1 that we can apply a rule from our set of rules to generate that transformation. Let us call <span xmlns:mml="http://www.w3.org/1998/Math/MathML" id="IEq1"><math id="M10" overflow="linebreak"><msub><mtext>M</mtext><msup><mtext>a</mtext><mo>′</mo></msup></msub></math></span> the molecule produced that way, and <span xmlns:mml="http://www.w3.org/1998/Math/MathML" id="IEq2"><math id="M12" overflow="linebreak"><msub><mtext>a</mtext><msup><mtext>ij</mtext><mo>′</mo></msup></msub></math></span> its bond orders. Let us now calculate the sum of orders of <span xmlns:mml="http://www.w3.org/1998/Math/MathML" id="IEq3"><math id="M14" overflow="linebreak"><msub><mtext>M</mtext><msup><mtext>a</mtext><mo>′</mo></msup></msub></math></span>. Then, by applying the rule, we have <span xmlns:mml="http://www.w3.org/1998/Math/MathML" id="IEq4"><math id="M16" overflow="linebreak"><msub><mtext>a</mtext><msup><mtext>ij</mtext><mo>′</mo></msup></msub></math></span> = a<sub>ij</sub> − 1 and therefore <span xmlns:mml="http://www.w3.org/1998/Math/MathML" id="IEq5"><math id="M18" overflow="linebreak"><mrow><mfenced close="|" open="|" separators=""><mrow><msub><mi>b</mi><mtext>ij</mtext></msub><mo>-</mo><msub><mi>a</mi><msup><mtext>ij</mtext><mo>′</mo></msup></msub></mrow></mfenced><mo>=</mo><mfenced close="|" open="|" separators=""><mrow><msub><mtext>b</mtext><mtext>ij</mtext></msub><mo>-</mo><msub><mtext>a</mtext><mtext>ij</mtext></msub></mrow></mfenced><mo>-</mo><mn>1</mn></mrow></math></span>. For the same reason, <span xmlns:mml="http://www.w3.org/1998/Math/MathML" id="IEq6"><math id="M20" overflow="linebreak"><mrow><mfenced close="|" open="|" separators=""><mrow><msub><mtext>b</mtext><mtext>kl</mtext></msub><mo>-</mo><msub><mtext>a</mtext><msup><mtext>kl</mtext><mo>′</mo></msup></msub></mrow></mfenced><mo>=</mo><mfenced close="|" open="|" separators=""><mrow><msub><mtext>b</mtext><mtext>kl</mtext></msub><mo>-</mo><msub><mtext>a</mtext><mtext>kl</mtext></msub></mrow></mfenced><mo>-</mo><mn>1</mn></mrow></math></span>. Moreover, <span xmlns:mml="http://www.w3.org/1998/Math/MathML" id="IEq7"><math id="M22" overflow="linebreak"><mrow><msub><mtext>a</mtext><msup><mtext>jk</mtext><mo>′</mo></msup></msub><msub><mrow><mspace width="0.333333em"></mspace><mtext>= a</mtext></mrow><mtext>jk</mtext></msub><mrow><mo>+</mo><mn>1</mn></mrow></mrow></math></span>, and since a<sub>jk</sub> is smaller than b<sub>jk</sub>, we also have <span xmlns:mml="http://www.w3.org/1998/Math/MathML" id="IEq8"><math id="M24" overflow="linebreak"><mrow><mfenced close="|" open="|" separators=""><mrow><msub><mtext>b</mtext><mtext>jk</mtext></msub><mo>-</mo><msub><mtext>a</mtext><msup><mtext>jk</mtext><mo>′</mo></msup></msub></mrow></mfenced><mo>=</mo><mfenced close="|" open="|" separators=""><mrow><msub><mtext>b</mtext><mtext>jk</mtext></msub><mo>-</mo><msub><mtext>a</mtext><mtext>jk</mtext></msub></mrow></mfenced><mo>-</mo><mn>1</mn></mrow></math></span>. The only bond we did not choose to change is a<sub>li</sub>. The order <span xmlns:mml="http://www.w3.org/1998/Math/MathML" id="IEq9"><math id="M26" overflow="linebreak"><msub><mtext>a</mtext><msup><mtext>ij</mtext><mo>′</mo></msup></msub></math></span> of the transformed bond is either closer to b<sub>li</sub> than was a<sub>li</sub>, then the difference of the sum of absolute order differences is reduced by 4, or is further from b<sub>li</sub>, and this sum is reduced by 2. Therefore, if M<sub>a</sub> and M<sub>b</sub> are different, we can apply a rule from this set of rules that will decrease the sum of absolute order differences by at least 2 and at most 4.</p></section><section id="FPar6"><h5 class="pmc_sec_title"><strong>Lemma 3</strong></h5>
<p id="Par33">
<em>Considering M</em>
<sub><em>a</em></sub>
<em>and M</em>
<sub><em>b</em></sub>
<em>an isomer of M</em>
<sub><em>a</em></sub>
<em>, the 19 rules described in Fig.</em> <a href="#Fig3" class="usa-link">3</a>
<em>allow us to transform M</em>
<sub><em>a</em></sub>
<em>into M</em>
<sub><em>b</em></sub>
<em>using at most</em> 3<em>/</em>4*(<em>N</em>
<sup>2</sup> − <em>N</em>) <em>single transformations, where</em>
<em>N</em>
<em>is the number of atoms, respecting the following constraints: the maximal valence is 4 and there cannot be two double bonds on the same atom in a 3 or 4 membered ring.</em>
</p></section><section id="FPar7"><h5 class="pmc_sec_title"><em>Proof</em></h5>
<p id="Par34">Let us consider M<sub>b</sub> an isomer of M<sub>a</sub>. If the sum of absolute order differences is not null, then M<sub>b</sub> is different from M<sub>a</sub> and using Lemma 2, we know we can apply a rule that will strictly decrease the sum of absolute order differences. This sum is obviously positive, is an integer, and is strictly decreasing each time we apply a transformation rule so it will converge to 0 in S/2 transformations at most, where S is the sum of absolute order differences between M<sub>a</sub> and M<sub>b</sub>. When this sum is null, all bond orders are the same, which means the molecules are the same. An upper estimation of the maximum bond order difference is obtained when M<sub>a</sub> only has triple bonds, which all have to be deleted. In that case, the sum of absolute order differences is: S = 3*(<em>N</em>
<sup>2</sup> − <em>N</em>)/2, where <em>N</em> is the number of atoms and (<em>N</em>
<sup>2</sup> − <em>N</em>)/2 the number of defined orders (since a<sub>ij</sub> = a<sub>ji</sub>). Therefore, since the sum decreases by at least 2, the maximum number of transformations we need to apply is 3*(<em>N</em>
<sup>2</sup> − <em>N</em>)/4.</p></section><section id="FPar8"><h5 class="pmc_sec_title"><em>Proof of the main claim</em></h5>
<p id="Par35">Given the workings of the algorithm (breadth-first, as explained in “<a href="#Sec12" class="usa-link">RetroPath2.0 core algorithm</a>” section), the number of iterations for generating all isomers is the number of iterations for generating the furthest one in term of bond order difference from our starting molecule. Therefore, applying Lemma 3, we know the maximum number of iterations of the algorithm is 3 * (<em>N</em>
<sup>2</sup> − <em>N</em>)/4.</p>
<p id="Par36">
<em>Notice that</em> although the number of iterations of the algorithm scales O(<em>N</em>
<sup>2</sup>), the number of transformation rules applied (i.e.: single reactions) is proportional to the number of isomers.</p></section><section id="FPar9"><h5 class="pmc_sec_title"><strong>Corollary 1</strong></h5>
<p id="Par37">
<em>The maximum number of iterations to generate all alkanes is N</em> − 1<em>, where N is the number of carbon atoms (hydrogens are not considered here).</em>
</p></section><section id="FPar10"><h5 class="pmc_sec_title"><em>Proof</em></h5>
<p id="Par38">Adapting the demonstration of Lemma 3, we have to consider the sum of absolute order differences of the farthest isomers that can be reached. Since alkanes are acyclic, the number of bonds is <em>N</em> − 1 (proven by a simple recurrence, the new atom being joined at a single point to the chain since the molecule is acyclic). Therefore, considering all bonds are different in the new molecule, the sum of absolute order differences is at most 2(<em>N</em> <em>−</em> 1). Therefore, the maximum number of iterations of the algorithm is <em>N</em> <em>−</em> 1.</p>
<p id="Par39">The isomer transformation algorithm was applied to generate all alkanes up to 18 carbon atoms using rule <em>R</em>
<sub>1</sub> of Fig. <a href="#Fig3" class="usa-link">3</a>, since it is the only rule with only single bonds. Results are presented in Table <a href="#Tab1" class="usa-link">1</a>, where it can be seen that Corollary 1 is verified in practice.
</p>

</p></div></div></section></section></section></section><section id="Sec6"><h3 class="pmc_sec_title">Virtual screening in the chemical space</h3>
<p id="Par40">In this section we used RetroPath2.0 to search all molecules that are at predefined distances of a given set of molecules. Such queries are routinely carried out in large chemical databases for drug discovery purposes [<a href="#CR31" class="usa-link" aria-describedby="CR31">31</a>], but in the present case we search similar structures in the entire chemical space. To perform search in the chemical space, we used a source set composed of 158 well-known monomers having a molecular weight up to 200 Da. Our rule set included the transformations colored green in Fig. <a href="#Fig3" class="usa-link">3</a> (i.e. transformation rules where double bonds are not transformed into cycles and conversely). For each monomer, RetroPath2.0 was iterated until no new isomers were generated. Each generated structures at a Tanimoto similarity greater than 0.5 from its corresponding monomer were retained (Tanimoto was computed using MACCS keys fingerprints [<a href="#CR32" class="usa-link" aria-describedby="CR32">32</a>]).</p>
<p id="Par41">Next, we wanted to probe if the generated structures exhibited interesting properties as far as polymer properties are concerned. To that end we first developed a QSPR model taking properties from [<a href="#CR33" class="usa-link" aria-describedby="CR33">33</a>]. We focused on polymer glass transition temperature <em>T</em>
<sub><em>g</em></sub> data [<a href="#CR34" class="usa-link" aria-describedby="CR34">34</a>]. The QSPR model was based on a random forest trained using RDKit fingerprints descriptors [<a href="#CR19" class="usa-link" aria-describedby="CR19">19</a>]. The obtained model had a leave-one-out cross-validation performance of Q<sup>2</sup> = 0.75. The model was then applied to predict the <em>T</em>
<sub>g</sub> for the set of enumerated isomers. Figure <a href="#Fig5" class="usa-link">5</a> compares the distribution of predicted <em>T</em>
<sub>g</sub> values for the enumerated isomers with those obtained from isomer structures available from PubChem. <em>T</em>
<sub>g</sub> values for enumerated isomers appeared evenly distributed around 301.86 ± 25.69 K compared with the isomers that were available in PubChem (331.66 ± 46.19 K). This shift in the <em>T</em>
<sub>g</sub> values could be explained by the difference in distribution that necessarily exists between the isomers that are present in PubChem and the total number of enumerated isomers. As we lower the Tanimoto threshold, some monomers might become underrepresented in terms of isomer availability in PubChem. Additional file <a href="#MOESM2" class="usa-link">2</a>: Figure S3 shows the distributions of both sets of isomers in function of the threshold. The increased ability of selecting polymers with <em>T</em>
<sub>g</sub> above or below room temperature for the enumerated set compared with the PubChem isomers is a desirable feature, as this parameter will determine the mechanical properties of the polymer [<a href="#CR35" class="usa-link" aria-describedby="CR35">35</a>]. In that way, performing a virtual screening of the chemical space of isomers of the reference monomers opens the possibility to engineering applications with improved polymer design.
</p>
<figure class="fig xbox font-sm" id="Fig5"><h4 class="obj_head">Fig. 5.</h4>
<p class="img-box line-height-none margin-x-neg-2 tablet:margin-x-0 text-center"><img class="graphic" src="https://cdn.ncbi.nlm.nih.gov/pmc/blobs/b549/5736515/2c70c9a039c6/13321_2017_252_Fig5_HTML.jpg" loading="lazy" id="MO9" height="582" width="638" alt="Fig. 5"></p>
<div class="p text-right font-secondary"><a href="figure/Fig5/" class="usa-link" target="_blank" rel="noopener noreferrer">Open in a new tab</a></div>
<figcaption><p>Distributions of predicted T<sub>g</sub> values for enumerated isomers and for isomers found in PubChem. Distribution of predicted polymer glass transition temperature <em>T</em>
<sub>g</sub> for enumerated isomers and for isomers found in Pubchem of a reference set of 158 monomers with a Tanimoto similarity greater than 0.5</p></figcaption></figure><p id="Par42">Moreover, we were interested in determining how many of the starting 158 monomers were accessible through biosynthesis. Namely, how many of the compounds can be synthesized by engineering a metabolic pathway in a chassis organism. This computation can be accomplished by RetroPath2.0 by defining all naturally produced chemicals as sinks in the workflow and using a collection of known enzymatic reaction rules in reversed mode. The process has been described in detailed elsewhere [<a href="#CR17" class="usa-link" aria-describedby="CR17">17</a>]. Through the application of the rules in a retrosynthetic fashion, it is possible to determine the routes that connect the target compounds to the natural precursors. Of the 158 available monomers, using the RetroPath2.0 workflow downloaded from MyExperiment.org [<a href="#CR36" class="usa-link" aria-describedby="CR36">36</a>], we were able to identify 17 compounds that can be naturally synthetized (Fig. <a href="#Fig6" class="usa-link">6</a>a). We provide in an archive containing the list of pathways for those 17 compounds.

<p id="Par44">In this section we are interested in searching chemical structures in the chemical space optimizing biological activities. This type of search can be solved using inverse QSAR procedures [<a href="#CR37" class="usa-link" aria-describedby="CR37">37</a>]. Inverse QSAR requires to first building a QSAR equation predicting activities from structure and then either (1) inverting the equation and enumerating structures matching a given activity [<a href="#CR37" class="usa-link" aria-describedby="CR37">37</a>] or (2) searching in the chemical space structures similar to those used to build the QSAR equation [<a href="#CR33" class="usa-link" aria-describedby="CR33">33</a>] but having optimized activities. The second approach makes use of either deterministic methods such as lattice enumeration [<a href="#CR38" class="usa-link" aria-describedby="CR38">38</a>] or stochastic searches.</p>
<p id="Par45">We propose here to use RetroPath2.0 to solve the inverse QSAR problem using a stochastic approach with isomer transformation rules and enzymatic rules for biosynthetic accessibility. To this end, we selected a dataset of 47 aminoglycosides structures for which antibacterial activities have been measured using a MIC assay [<a href="#CR39" class="usa-link" aria-describedby="CR39">39</a>]. The dataset is composed of natural aminoglycosides (gentamicin, tobramycin, neomycin, kanamycin A and B, paromomycin, ribostamycin and neamine) to which are added synthetic structures built on a neamine scaffold. This dataset has already been used to build a QSAR model based on CoMFA analysis leading to a Q2 of 0.6 for a Leave-One-Out (LOO) procedure [<a href="#CR39" class="usa-link" aria-describedby="CR39">39</a>]. We provide in Additional file <a href="#MOESM1" class="usa-link">1</a> a QSAR workflow that makes use of RDKit fingerprints [<a href="#CR19" class="usa-link" aria-describedby="CR19">19</a>] and random forest as a learner leading to a higher Q2 (0.7) for LOO. With that QSAR in hand we run RetroPath2.0 with a source set composed of the 47 aminoglycosides used in the training set, and two different reaction rules sets. The first set is extracted from the transforming enumeration rules depicted in Fig. <a href="#Fig3" class="usa-link">3</a>, the second set is composed of enzymatic reaction rules leading to neamine (an aminoglycoside) biosynthesis from glucose. Reaction rules for the second set were computed as explained in the method section resulting in 94 rules specific to the biosynthesis of aminoglycosides.</p>
<p id="Par46">In both cases, reactions rules were fired on the initial source set composed of 47 structures. All rule products were ranked according to their predicted activities as calculated by the QSAR and were selected for the next iteration according to a tournament procedure described in the methods section which derives from [<a href="#CR40" class="usa-link" aria-describedby="CR40">40</a>]. The Fig. <a href="#Fig7" class="usa-link">7</a>a, b below gives the top activity and the average population activity vs. iteration. The most active structures found by each rule set are also drawn in Fig. <a href="#Fig7" class="usa-link">7</a>c, d.

<p id="Par48">In this last example we use enzymatic reaction rules in an attempt to complete the metabolome of species used in biotechnology. We are motivated here by current efforts invested to complete the knowledge on the metabolism of various organisms [<a href="#CR6" class="usa-link" aria-describedby="CR6">6</a>, <a href="#CR7" class="usa-link" aria-describedby="CR7">7</a>, <a href="#CR15" class="usa-link" aria-describedby="CR15">15</a>]. The benefits are numerous and include the identification of relevant biomarkers for many diseases; for personalized nutrition advice; and also for searching for relevant indicators and metabolites of plant and animal stress in agricultural practices and breeding programs. Additionally, knowing the metabolic space of microbes is an essential step for optimizing metabolic engineering and creating synthesis pathways for new compounds for industrial applications.</p>
<p id="Par49">Experimental evidences from metabolomics analyses are often informing us that with currently known metabolites one cannot cover the ranges of masses found in actual samples, and consequently there is a need of completing the metabolomes of interest. This need is clearly seen in the Human Metabolome Database (HMDB) where the number of reported masses has recently grown from 20,931 in 2013 [<a href="#CR41" class="usa-link" aria-describedby="CR41">41</a>] to 74,461 (at the time this manuscript was written), while annotated metabolites in metabolic databases are still in the range of 1847 (HumanCyc). Despite such a growth in databases, a significant amount of spectral peaks remains unassigned. This high fraction of unassigned peaks might be due to several factors including isotope, adduct formation, ion fragmentation, and multimers. Besides such sources of uncertainty in samples, many unassigned peaks should also be due to promiscuous activities of enzymes not yet characterized because of the lack of an appropriate description of the mechanisms of enzyme promiscuity.</p>
<p id="Par50">To gain insights into those mechanisms enabling promiscuity, reaction rules have been shown to be appropriate [<a href="#CR21" class="usa-link" aria-describedby="CR21">21</a>] in particular the rules allowing to focus on the center of the reactions. To this end, several enzymatic reaction rules have been proposed such as those derived from bond-electron matrices [<a href="#CR42" class="usa-link" aria-describedby="CR42">42</a>], on the smallest molecular substructure changing during transformations [<a href="#CR9" class="usa-link" aria-describedby="CR9">9</a>], or on reaction rules that code for variable environments at reaction centers (see [<a href="#CR7" class="usa-link" aria-describedby="CR7">7</a>] and “<a href="#Sec10" class="usa-link">Methods</a>” section). That latter reaction rule system codes for changes in atom bonding environments where the reaction is taking place and the environment can range from including only the atoms participating to the reaction center to the entire set of atoms and molecules participating to the reaction. The advantage of that latter approach is that the size of the environment (named diameter) can be tuned to control the combinatorial explosion of possible products.</p>
<p id="Par51">The degree of plasticity in metabolic networks that is uncovered by variable reaction center diameter is actually revealing an intrinsic feature of organisms linked to their adaptability, i.e. enzyme promiscuity. Promiscuity stands for the ability of enzymes to catalyze more than one reaction or to accept more than one substrate, a mechanism which can be traced to the evolutionary origins of enzymatic functions. Mimicking nature, such enzyme versatility can provide novel ways for biosynthesizing metabolite and even bioproducing non-natural molecule. To that end, the variable diameter method has shown itself to be especially well-suited for modeling the mechanisms of enzyme promiscuity as it has already enabled the experimentally validated discovery of a novel metabolite in <em>E. coli</em> and of the promiscuous enzymes producing it [<a href="#CR21" class="usa-link" aria-describedby="CR21">21</a>].</p>
<p id="Par52">In this study, we make use of RetroPath2.0 to exemplify how variable reaction rule diameters can be used to complete the metabolome of <em>E. coli</em>. More precisely, we used as a source set all the metabolites present in <em>E. coli</em> iJO1366 model [<a href="#CR43" class="usa-link" aria-describedby="CR43">43</a>]. We first tested the two rule sets aforementioned, a set of about 100 reaction rules part of the BNICE framework [<a href="#CR42" class="usa-link" aria-describedby="CR42">42</a>] and a set of 50 reaction rules developed with the Sympheny software [<a href="#CR9" class="usa-link" aria-describedby="CR9">9</a>]. The reaction rules coded in the form of SMARTS string are provided in Supplementary at MyExperiment.org, along with the EC numbers corresponding to the rules. While the two rule sets were not developed to code only for <em>E. coli</em> reactions, for each EC number there is a corresponding enzyme annotated in <em>E. coli</em> so we kept all rules in the two sets. We then tested reaction rules with variable diameters using the procedure described in the method section to code for all <em>E. coli</em> metabolic reactions extracted from iJO1366 model. Rules were calculated for each reaction with diameters ranging from 2 to 16. Table <a href="#Tab2" class="usa-link">2</a> below provides the number of compound generated running RetroPath2.0 for one iteration on the metabolites of the iJO1366 model and the rules sets mentioned above (see “<a href="#Sec10" class="usa-link">Methods</a>” section for additional details).

The spectra downloaded corresponded to a study aimed at probing the dynamics of isotopically labeled molecules (i.e. <sup>13</sup>C labeled glucose) [<a href="#CR45" class="usa-link" aria-describedby="CR45">45</a>]. We observe that the Sympheny and BNICE rules sets give results similar to those obtained by the D6 rule set, albeit with a higher number of annotations per peak.</p>
<p id="Par56">In all cases the rule sets produced compounds not present in the <em>E. coli</em> model but with corresponding masses in the MS spectra. Additional file <a href="#MOESM4" class="usa-link">4</a>: Table S2 give a list of 40 such compounds having an identifier in MetaNetX [<a href="#CR11" class="usa-link" aria-describedby="CR11">11</a>] and produced by three identical reactions (i.e. reactions having the same substrates and products) generated using the Sympheny, BNICE and D6 rule sets. The compounds were produced by 53 reactions, some compounds being produced by more than one reaction. We note that the 40 compounds have been generated by rule sets for which at least one gene in <em>E. coli</em> has been annotated with the same corresponding EC number. The 40 compounds are thus potential new <em>E. coli</em> metabolites and their presence should be further verified using for instance MS/MS analysis (Additional file <a href="#MOESM4" class="usa-link">4</a>: Table S2).</p></section></section><section id="Sec9"><h2 class="pmc_sec_title">Conclusions</h2>
<p id="Par57">In this paper we have presented a general method allowing one to explore the chemical space around a given molecule, or around a given set of molecules. The originality of the method is that the exploration is performed through chemical reactions rules. We have given a set of rules allowing us to generate any isomer of any given molecule of the chemical space. We also provide examples making use of reaction rules computed from enzymatic reactions. Using rules computed on known reactions has a definite advantage regarding the (bio)synthetic accessibility of the molecule produced, which is not necessarily the case for other techniques producing molecules de novo [<a href="#CR33" class="usa-link" aria-describedby="CR33">33</a>, <a href="#CR37" class="usa-link" aria-describedby="CR37">37</a>, <a href="#CR40" class="usa-link" aria-describedby="CR40">40</a>, <a href="#CR49" class="usa-link" aria-describedby="CR49">49</a>–<a href="#CR53" class="usa-link" aria-describedby="CR53">53</a>].</p>
<p id="Par58">Our method has been implemented into RetroPath2.0, a workflow running on the KNIME Analytics Platform [<a href="#CR18" class="usa-link" aria-describedby="CR18">18</a>]. RetroPath2.0 can easily be used with source molecules and reaction rules different than those presented in the paper. For instance the workflows provided in Additional file <a href="#MOESM1" class="usa-link">1</a> can be used with the reaction SMARTS rules and fragment libraries (as source compounds) of the DOGS software (inSili.com LLC [<a href="#CR4" class="usa-link" aria-describedby="CR4">4</a>]) developed for de novo drug design, other technique evolving molecules toward specific activities or properties [<a href="#CR40" class="usa-link" aria-describedby="CR40">40</a>, <a href="#CR50" class="usa-link" aria-describedby="CR50">50</a>–<a href="#CR52" class="usa-link" aria-describedby="CR52">52</a>] could also be implemented in RetroPath2.0 provided that one first codes reaction rules in SMARTS format.</p>
<p id="Par59">Aside from searching molecules having interesting properties and activities RetroPath2.0 can also be used to complete metabolic maps by proposing new metabolites biosynthesized through promiscuous enzymes, these new metabolites can in turn be used to annotate MS spectra and to that end we provide an interface with OpenMS [<a href="#CR23" class="usa-link" aria-describedby="CR23">23</a>]. Finally, RetroPath2.0 was originally developed to enumerate pathways producing a given target product from a source set of reactants. While we have benchmarked the workflow in the context of metabolic engineering, [<a href="#CR17" class="usa-link" aria-describedby="CR17">17</a>] it can also be used for synthesis planning as long as synthesis reaction rules are available.</p></section><section id="Sec10"><h2 class="pmc_sec_title">Methods</h2>
<section id="Sec11"><h3 class="pmc_sec_title">Generating reaction rules</h3>
<p id="Par60">All our reaction rules are represented in the form of reaction SMARTS [<a href="#CR14" class="usa-link" aria-describedby="CR14">14</a>]. Reaction rules used for canonical augmentation are provided in Fig. <a href="#Fig1" class="usa-link">1</a> and for isomer transformation in Figs. <a href="#Fig3" class="usa-link">3</a>, <a href="#Fig4" class="usa-link">4</a>, Additional file <a href="#MOESM2" class="usa-link">2</a>: Figure S2 and Additional file <a href="#MOESM5" class="usa-link">5</a>: Table S3. Enzymatic reaction rules were computed taking enzymatic reactions from MetaNetX version 2.0 [<a href="#CR11" class="usa-link" aria-describedby="CR11">11</a>]. To compute rules, we first performed an Atom–Atom Mapping (AAM) using the tool developed by [<a href="#CR46" class="usa-link" aria-describedby="CR46">46</a>] (Fig. <a href="#Fig8" class="usa-link">8</a>a). Next, multiple substrates reactions were decomposed into components (panel C and D in Fig. <a href="#Fig8" class="usa-link">8</a>). There are as many components as there are substrates and each component gives the transformation between one substrate and the products. Each product must contain at least one atom from the substrate according to the AAM. This strategy enforces that only one substrate can differ at a time from the substrates of the reference reaction when applying the rule.
</p>

<p id="Par62">We extracted more than 24,000 reaction components from MetaNetX reactions, each one of those leading to a rule at each diameter (from 2 to 16).</p>
<p id="Par63">We provide in Supplementary at MyExperiment.org a subset of 14,300 rules for <em>E. coli</em> metabolism. The rules were selected based on the MetaNetX binding to external databases and the iJO1366 whole-cell <em>E. coli</em> metabolic model [<a href="#CR43" class="usa-link" aria-describedby="CR43">43</a>]. We also provide enzymatic rules enabling the biosynthesis of aminoglycosides from Glucose. The reactions were extracted from the map00524 KEGG map [<a href="#CR47" class="usa-link" aria-describedby="CR47">47</a>], and rules were computed as above on reactions for which a MetaNetX identifier could be retrieved. The resulting set comprised 94 rules calculated for each diameter ranging from 2 to 16.</p></section><section id="Sec12"><h3 class="pmc_sec_title">RetroPath2.0 core algorithm</h3>
<p id="Par64">The RetroPath2.0 workflow essentially follows an algorithm proposed by some of us [<a href="#CR16" class="usa-link" aria-describedby="CR16">16</a>, <a href="#CR17" class="usa-link" aria-describedby="CR17">17</a>] and its workflow implementation, which has already been described in details [<a href="#CR17" class="usa-link" aria-describedby="CR17">17</a>], is summarized in Fig. <a href="#Fig9" class="usa-link">9</a>. We here focus on the different usages of RetroPath2.0 for the use cases provided in “<a href="#Sec2" class="usa-link">Results and discussions</a>” section.
</p>
<figure class="fig xbox font-sm" id="Fig9"><h4 class="obj_head">Fig. 9.</h4>
<p class="img-box line-height-none margin-x-neg-2 tablet:margin-x-0 text-center"><img class="graphic" src="https://cdn.ncbi.nlm.nih.gov/pmc/blobs/b549/5736515/163db32dbbed/13321_2017_252_Fig9_HTML.jpg" loading="lazy" id="MO13" height="226" width="785" alt="Fig. 9"></p>
<div class="p text-right font-secondary"><a href="figure/Fig9/" class="usa-link" target="_blank" rel="noopener noreferrer">Open in a new tab</a></div>
<figcaption><p>RetroPath2.0 KNIME workflow. Inner view of the “Core” node where the computation takes place. The “Source, Sink…” and “Rules” nodes parse the source, sink and rules input files provided by the user and standardize data so that it can be processed by downstream nodes. Definitions for source, sink, and rule sets are provided in the text. The outer loop (“Source” loop) iterates over each source compounds, while the inner loop (“Length” loop) allows to iterate the process up to a maximum number of steps predefined by the user. The nodes (1) “FIRE”, (2) “PARSE”, (3) “UPDATE SOURCE…” and (4) “BUILD” are sequentially executed at each inner iteration. Respectively, they (1) apply all the rules on source compounds, (2) parse and standardize new products, (3) update the lists of source and sink compounds for the next iteration and (4) merge results that will be written by the node “Write global results”. Once the maximum number of steps is reached (or no new product is found), the “Compute scope” node identify the scope linking each source to the sink compounds, then these results are written by the node “Write per source results”. Only the main nodes involved in the process are shown</p></figcaption></figure><p id="Par65">In all cases the workflow performs the generation of structures in a breadth-first way by applying iteratively the same procedure. An iteration starts by applying reaction rules to each of the compounds of a source set. For each compound, the products are computed using the RDKit KNIME nodes one-component or two-component reactions [<a href="#CR19" class="usa-link" aria-describedby="CR19">19</a>]. Products are sanitized (removal of structures having incorrect valence), standardised and duplicates are merged. The set of products will become the new source set for the next iteration. The workflow iterates until a predefined number of iterations is reached or until the source set is empty.</p>
<p id="Par66">In the case of isomer augmentation (workflow RetroPath2.0-Mods-isomer-augmentation, “<a href="#Sec3" class="usa-link">Isomer enumeration</a>” sections) the initial source set is composed of a single carbon atom and the rule used is <em>R</em>
<sub>1</sub> in Fig. <a href="#Fig1" class="usa-link">1</a>, since it is the only rule that will produce acyclic molecules. The rule is fired on the source set, and the products become the new source set in the next iteration. The workflow is iterated a number of times equal to <em>N</em> − 1, where <em>N</em> is the number of atoms one wishes the final molecule to have.</p>
<p id="Par67">In the case of isomer transformation (workflow RetroPath2.0-Mods-isomer-transformation, “<a href="#Sec3" class="usa-link">Isomer enumeration</a>” and “<a href="#Sec6" class="usa-link">Virtual screening in the chemical space</a>” section) the initial source set is composed of a molecule that is filled with the appropriate number of hydrogens using the RDKit KNIME node Add Hs. At each iteration rules are fired on the source set and the products obtained become the new source set for the next iteration. As an additional last step of each iteration, products that have already been processed in a previous iteration are filtered out before building the next source set. This necessitates maintaining a set (named sink) comprising all molecules so far generated. All products that have already been obtained are removed from the product set and the remaining molecules are (1) added to the sink set and (2) used as the new source set for the next iteration. This avoids applying reactions on the same products during subsequent iterations. Disconnected structures are removed from the results by filtering out any product having several disconnected components (according to the SMILES representation). When enumerating alkane, disconnected structures represents between 50 and 66% (depending of the alkane size) of the generated structures before filtering and merging duplicates. To generate the results of Table <a href="#Tab1" class="usa-link">1</a>, since we are enumerating alkanes (no multiple bonds or cycles), the rule to be used is <em>R</em>
<sub>1</sub> in Fig. <a href="#Fig3" class="usa-link">3</a>. To enumerate the isomers of the monomers in “<a href="#Sec6" class="usa-link">Virtual screening in the chemical space</a>” section, if we prohibit the transformation of multiple bonds into cycles and thus keep the number of single, double and triple bonds constant, the rules to be used are <em>R</em>
<sub>1</sub>, <em>R</em>
<sub>5</sub> and <em>R</em>
<sub>9</sub> in Fig. <a href="#Fig3" class="usa-link">3</a> (also found in Additional file <a href="#MOESM2" class="usa-link">2</a>: Figure S2 since the monomers used do not contain triple bonds). Since this algorithm can become computationally intensive, we also provide an additional workflow (called RetroPath2.0-Mods-isomer-transformation-queue) to deal with memory management. This workflow illustrates how to introduce a FIFO data structure for the source set (i.e. queue containing structures upon which rules will be fired) and use it for iteratively firing rules on small chunks of structures (e.g. chunk of 20 structures), new products obtained are then added to the source queue. Interestingly, the breadth-first approach for generating the structures can be replaced by a depth-first approach by replacing the queue (first in, first out structure) by a stack (last in, first out structure).”</p>
<p id="Par68">In the case of inverse-QSAR (workflow RetroPath2.0-Mods-iQSAR, “<a href="#Sec7" class="usa-link">Search for molecules maximizing biological activities</a>” section), the source set initially comprises the molecules used in the training set when building the QSAR. At each iteration, one or two molecules are chosen at random from the source set depending on the rule set that is being used (one molecule with enzymatic reaction rules, two molecules with isomer transformation rules). Rules are then fired on the selected molecules and an activity is predicted for each product using the QSAR equation. The source set is updated retaining molecules according to a selection tournament procedure borrowed from [<a href="#CR40" class="usa-link" aria-describedby="CR40">40</a>]. Briefly, the initial source set (i.e. the set of structures used at the start of the current iteration) is merged with the product set (i.e. the set of structures obtained after firing the rules). This merged set is then randomly split into 10 subsets and the 10 top best structures from each subset are retained according to their predicted activity. Finally, all the retained structures are pooled together to form the updated source set to be used at the next iteration. The workflow is iterated a (user) predefined number of times.</p>
<p id="Par69">In the case of <em>E. coli</em> metabolic network completion (workflow RetroPath2.0-Mods-metabolomics, “<a href="#Sec8" class="usa-link">Metabolome completion and metabolomics</a>” section), we provide three workflows. The first workflow is RetroPath2.0, which is fully described in [<a href="#CR17" class="usa-link" aria-describedby="CR17">17</a>] and is similar to the isomer transformation one. Here, RetroPath2.0 produces a list of molecules obtained using <em>E. coli</em> enzymatic reaction rules (see “<a href="#Sec11" class="usa-link">Generating reaction rules</a>” section). The second workflow takes as input the products generated by RetroPath2.0, computes the exact mass for each product and prepare files to be read by OpenMS nodes for MS data peak assignment [<a href="#CR23" class="usa-link" aria-describedby="CR23">23</a>]. The last workflow is built with OpenMS nodes, it reads several MS data files in mzML format, two lists of adducts in positive and negative modes, and the files generated by the second workflow (containing RetroPath2.0 generated products with masses). The workflow searches for each compound the corresponding peak in the MS spectra. The workflow was parameterized for metabolomics analysis as described in OpenMS manual [<a href="#CR48" class="usa-link" aria-describedby="CR48">48</a>], the AccurateMassSearch node was set to negative ion mode as the experiment were carried out with an LTQ-Orbitrap instrument operating in negative FT mode (cf. protocols in [<a href="#CR44" class="usa-link" aria-describedby="CR44">44</a>]).</p>
<p id="Par70">Further details on how to run all the above workflows are provided in the Supplementary at MyExperiment.org.</p></section></section><section id="sec27"><h2 class="pmc_sec_title">Additional files</h2>
