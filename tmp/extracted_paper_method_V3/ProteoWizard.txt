sample_description: The samples used in the research were grab samples collected from the effluent of a wastewater treatment plant in Warburg, Germany (Stadtwerke Warburg GmbH). These effluent samples contain a high organic load, resulting in pronounced matrix-associated effects in high-resolution mass spectrometry (HRMS), such as signal overlay—making them particularly suitable for robustness testing of the centroiding algorithm. The sampling and sample preparation protocols followed those detailed in Hohrenk et al. (2020) [24]. The samples were analyzed using HPLC-HRMS for both MS1 and MS2 spectra, with all illustrative examples in the paper focusing on MS1 spectra acquired in electrospray ionization positive mode (ESI+); however, the algorithm is explicitly designed to support both ESI+ and ESI− measurements. Importantly, the chromatographic domain was intentionally neglected during algorithm development—i.e., spectra were treated as independent observations—to ensure universal applicability regardless of whether prior chromatographic separation was performed.
software_configuration_description: ProteoWizard's msConvert tool (version not explicitly stated, but implied by context of compatibility with Thermo *.raw files and mzXML export) was used solely for format conversion—not for centroiding. Specifically, raw instrumental data files from the Q Exactive Orbitrap mass spectrometer (Thermo Scientific) in proprietary *.raw format were converted to open-standard profile-mode *.mzXML files to facilitate import into Python (v3.9), R (v4.0.4), and Julia (v1.6.3) programming environments. No centroiding, smoothing, filtering, or peak-picking options were enabled in msConvert; it was configured strictly for lossless profile-data preservation and format interoperability. The conversion preserved full-scan MS1 (m/z 100–1000) and data-dependent MS2 spectra at specified resolutions (70,000 at m/z 200 for MS1; 17,500 at m/z 200 for MS2). Third-party packages required for downstream processing are listed in Table S3 of the supplementary material and are automatically installed in the ready-to-use application.

software_configuration_description: The mzMLb format was implemented as part of the open-source, cross-platform ProteoWizard software libraries and tools (available at https://github.com/biospi/pwiz). The reference implementation uses the 'msconvert' command-line tool for conversion from proprietary vendor formats to mzMLb. For benchmarking write performance, msconvert was executed 10 times per file on a Linux workstation (Dell T5810, Intel Xeon CPU E5-1650 v3, 32 GB RAM, 3 TB HDD, Ubuntu Linux v18.04), with Linux memory cache explicitly cleared after each invocation to eliminate caching artifacts. For read performance evaluation, a custom C++ benchmarking tool named 'readBench' was developed, which leverages the ProteoWizard API to ensure consistent, format-agnostic reading across all file types. The tool supports two access patterns: (i) random single-spectrum access repeated 10,000 times, and (ii) random block-sequential access of 10 spectra repeated 1,000 times (totaling 10,000 spectrum accesses), with each configuration repeated 10 times for statistical robustness. Compression configurations included zlib, Numpress+zlib, BLOSC (with LZ4HC), and combinations thereof; mzLinear prediction and mantissa truncation were enabled/disabled systematically. Default HDF5 chunk size was set to 1024 KB, based on empirical optimization showing plateaued compression gains and deteriorating write speed beyond this point.

sample_description: The study used two main experimental datasets: (1) a bovine spike-in experiment involving an equimolar six-bovine-protein tryptic digest (Bruker-Michrom) spiked at nine concentrations (48, 16, 4, 2, 1, 0.5, 0.25, 0.05, and 0.025 fmol/μL) into a constant background matrix of digested S. cerevisiae soluble lysate (0.75 μg/μL), where the yeast digest was prepared from 400 μL of 5.1 μg/μL BY4741 strain proteins solubilized in 50 mM ammonium bicarbonate (ABC), reduced with 6 μL 500 mM TCEP at 60°C for 30 min, alkylated with 8 μL 500 mM iodoacetamide for 30 min at RT, quenched with 5 μL 500 mM DTT for 15 min at 37°C, and digested with 40 μL of 2 μg/μL TPCK-treated trypsin for 4 h at 37°C, followed by acidification with 60 μL 10% TFA; and (2) a comparative proteomics experiment using rapamycin-treated yeast (S. cerevisiae), though specific sample preparation details for the rapamycin experiment were not provided in the text. All samples were analyzed via nanoLC-MS/MS using 2 μL injections.
software_configuration_description: ProteoWizard msconvert was used to process raw mass spectrometry data and implement the demultiplexing algorithm for overlapping-window DIA data. Specifically, the demultiplexing algorithm—based on linear non-negative least squares (Lawson-Hanson solver) and designed for partially overlapping isolation windows—was integrated into ProteoWizard msconvert to produce full demultiplexed spectra. The algorithm operates on MS/MS spectra acquired with 20 m/z overlapping windows (e.g., alternating cycles offset by −10 m/z), assigning fragment ion signals to correct 10 m/z demultiplexing regions (spanning 490–900 m/z in 10 m/z steps). It solves the matrix equation XA = Y, where X is a 41×41 design matrix encoding scan-to-demultiplexing-region inclusion (1 if included, 0 otherwise), Y is the observed intensity matrix (41×m, m = number of fragment ions of interest), and A is the unknown intensity matrix (41×m) constrained to non-negative values. Special-purpose heuristics enable block-wise approximate solving for computational efficiency (~1000 transitions from ~56,000 spectra in 10 min). The implementation supports arbitrary window widths and overlaps—not limited to 20 m/z width / 10 m/z overlap—and outputs demultiplexed spectra compatible with downstream analysis tools like Skyline.

It was applied to extract tandem mass spectra from a Thermo Velos LTQ Orbitrap RAW file. The extracted data were converted into text-based MS2 files and subsequently searched against the UniProt human protein database using IP2 (with ProLuCID and DTASelect 2). Search parameters included: precursor mass tolerance of 50 ppm, fragment mass tolerance of 600 ppm, semi-tryptic peptides with at most one missed cleavage, carbamidomethylation (Cys) as a fixed modification, and oxidation (Met) and deamidation (Asn/Gln) as variable modifications (at most one per peptide). A target-decoy strategy was employed to control the false discovery rate (FDR) at 1% at the peptide-spectrum match (PSM) level. sample_description: The research evaluated the software's cross-platform performance using numerous simple and complex sample types from four instrument platforms: AB SCIEX Triple TOF 5600 (UPS1 human, E. coli, Rat Liver), Agilent 6530/6550 QqTOF (Bovine 6, Human Serum), Thermo Scientific Q-Exactive (Bovine 6, Jurkat human), and Waters Synapt G2/G2-S QqTOF (Bovine 6, Yeast, E. coli, K562 human). Sample complexity increased from top to bottom within each vendor group in Table 1. All raw datasets were publicly available through MassIVE (http://massive.ucsd.edu/ProteoSAFe). Samples were selected for software evaluation—not necessarily under optimal instrument acquisition conditions—and were not uniformly run across all platforms; interplatform comparisons were explicitly avoided. Sample preparation and acquisition details were provided only briefly in the Supporting Information.
software_configuration_description: ProteoWizard (specifically msConvert) was configured with three custom signal processing filters: CantWaiT (wavelet-based peak-picking), Turbocharger (precursor charge determination), and a Poisson model-based deisotoper. CantWaiT was applied to MS/MS spectra (though optionally usable on MS1) using a Ricker ('Mexican Hat') wavelet, adaptive wavelet scales dependent on m/z spacing (computed via 10-point sliding window), and limited to 10 scales; it performed single-pass local maxima detection with minimum m/z spacing of 0.1 Da (0.01 Da for Thermo Q-Exactive) and SNR thresholding (default SNR = 1.0, adjustable from 0.0 to >2.0); no preprocessing (smoothing/resampling) was required. Turbocharger used three scoring criteria—m/z spacing (SSE-based p-value vs. 10,000 simulated random chains), relative intensity distribution (Poisson model + KL divergence p-value vs. 10,000 simulated random peak sets from top 200 peaks across nine survey scans), and intensity rank-sum (p-value from fraction of possible rank-sums)—and searched charge states per dataset as specified in Table 1 (e.g., +2 to +14 for Agilent 6550 Human Serum); it analyzed two survey spectra per MS/MS spectrum (preceding for Thermo/Waters; one preceding + one following for AB SCIEX/Agilent), used isolation windows of ±1.00 m/z (AB SCIEX), ±1.25 m/z (Thermo), or ±1.50 m/z (others), and enforced a relative intensity p-value < 0.30 for final assignment, with fallback to default charges (+2 for Thermo, +2/+3 for Agilent/Waters, no charge for AB SCIEX) if no chain met criteria. Deisotoping used the same Poisson/KL approach but with 100 ppm m/z spacing tolerance (vs. fixed tolerance in Turbocharger) and charge range 1–3 by default; chains were removed if SSE and KL scores fell below length-dependent cutoffs (listed in Table S1). Subscan summation was applied to Waters data using msConvert’s built-in algorithm (summing intensities at identical m/z across MS/MS spectra sharing precursor m/z within ±0.05 m/z and retention time within 30 s). All parameters and command-line usage examples were documented in Supporting Information Tables S2–S6.
