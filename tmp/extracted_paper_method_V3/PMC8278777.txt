</div></section></section><section aria-label="Article content"><section class="body main-article-body"><section class="abstract" id="ABS1"><h2>Abstract</h2>
<p id="P1">Characterization of complex biological systems based on high-throughput protein quantification through mass spectrometry commonly involves differential expression analysis between replicate samples originating from different experimental conditions. Here we present Proteomics INTegrator (PINT), a new user-friendly web-based platform-independent system to store, visualize, and query proteomics experiment results. PINT provides an extremely flexible query interface that allows advanced Boolean algebra-based data filtering of many different proteomics features such as confidence values, abundance levels or ratios, dataset overlaps, sample characteristics, as well as UniprotKB annotations, which are transparently incorporated into the system. In addition, PINT allows developers to incorporate data visualization and analysis tools, such as PSEA-Quant and Reactome pathways analysis, for dataset enrichment analysis. PINT serves as a centralized hub for large scale proteomics data and as a platform for data analysis, facilitating interpretation of proteomics results and expediting biologically relevant conclusions.</p>
<section id="kwd-group1" class="kwd-group"><p><strong>Keywords:</strong> Proteomics, Mass Spectrometry, data filtering, data query, data visualization, enrichment analysis, Java GWT</p></section></section><section class="abstract" id="ABS2"><h2>Graphical Abstract</h2>
<p class="img-box line-height-none margin-x-neg-2 tablet:margin-x-0 text-center"><img class="graphic" src="https://cdn.ncbi.nlm.nih.gov/pmc/blobs/1cd5/8278777/4d8d0b967ee3/nihms-1718947-f0001.jpg" loading="lazy" height="361" width="640" alt="graphic file with name nihms-1718947-f0001.jpg"></p></section><section id="S1"><h2 class="pmc_sec_title">1. INTRODUCTION</h2>
<p id="P3">Mass spectrometry-based proteomics encompasses many different types of experimental techniques to analyze protein samples. Proteomics has become a very powerful means to perform high-throughput rapid and deep proteome sample characterization analyses, and new technological improvements continue to quickly evolve <sup><a href="#R1" class="usa-link" aria-describedby="R1">1</a>–<a href="#R4" class="usa-link" aria-describedby="R4">4</a></sup>. For example, in the past 15 years, proteomics experiments have progressed from straightforward qualitative determination of proteomes, to quantitative protein expression profiles, to comprehensive protein interactome analysis <sup><a href="#R5" class="usa-link" aria-describedby="R5">5</a></sup>. A great variety of bioinformatics tools have been developed to accompany each technological advance in proteomics <sup><a href="#R6" class="usa-link" aria-describedby="R6">6</a>, <a href="#R7" class="usa-link" aria-describedby="R7">7</a></sup>. Typically, each new bioinformatic tool applies a specific algorithm, designed and implemented for a particular type of data or goal, and generates a different output. Furthermore, downstream data analyses <sup><a href="#R8" class="usa-link" aria-describedby="R8">8</a></sup> often requires data integration across replicate sample measurements, additional statistical assessments, as well as annotation enrichment analysis. In these cases, it is common to use in-house developed scripts or data analysis tools such as Microsoft Excel, MATLAB or R, with the consequence that the final steps of data analysis often result in custom data tables that are difficult to fully integrate in publicly available proteomics databases such as the ProteomeXchange <sup><a href="#R9" class="usa-link" aria-describedby="R9">9</a></sup> because these public repositories require standard data formats. Other online resources such as Zenodo (<a href="https://zenodo.org/" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://zenodo.org/</a>), GitHub (<a href="https://github.com/" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/</a>), or ResearchGate (<a href="https://www.researchgate.net/" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://www.researchgate.net/</a>) among others, allow scientists, following good bioinformatic practices, to share both the output of these custom analyses and the scripts used to generate them. However, this doesn’t solve the problem of how to integrate the results of these analyses with other datasets or databases due to their non-standard format.</p>
<p id="P4">Furthermore, since a single proteomics laboratory can generate a large amount of data, the long-term storage and availability of data becomes problematic. The data storage issue is further complicated by the great variety of experimental designs that are used in proteomics which makes it very difficult to encode and store in a database. Experimental design or experimental metadata are usually captured in a minimum fashion in public repositories, and the link between the actual proteomics results and the experimental metadata is lost or minimized when stored in these repositories.</p>
<p id="P5">Current public databases for MS-based proteomics datasets such as PRIDE <sup><a href="#R10" class="usa-link" aria-describedby="R10">10</a></sup>, GPMDB <sup><a href="#R11" class="usa-link" aria-describedby="R11">11</a></sup>, PeptideAtlas <sup><a href="#R12" class="usa-link" aria-describedby="R12">12</a></sup> or MassIVE <sup><a href="#R13" class="usa-link" aria-describedby="R13">13</a></sup> mostly focus on hosting the raw data and result files, and some of them re-process the data using their own pipelines. PRIDE, allows to filter datasets by features such as instrument type, species, tissue, disease, modifications or experiment types through their PRIDE-Archive browser <sup><a href="#R14" class="usa-link" aria-describedby="R14">14</a></sup>, and provides a simple search box in which users can look for datasets containing certain peptide or protein. However, it doesn’t allow to query over more details from the data, such as actual scores or relative ratios. Others such as Panorama Public <sup><a href="#R15" class="usa-link" aria-describedby="R15">15</a></sup> or ProteomicsDB <sup><a href="#R16" class="usa-link" aria-describedby="R16">16</a></sup> allow a user to query to a certain extent specific details about a dataset. Panorama Public, a public repository for quantitative datasets processed in Skyline <sup><a href="#R17" class="usa-link" aria-describedby="R17">17</a></sup> provides a query system to retrieve datasets containing certain proteins or peptides and showing target-proteomics-related features of them. But it is not possible, for example, to identify a set of proteins that have been differentially expressed in a certain tissue and to compare them to the ones reported in another dataset. In case of ProteomicsDB, it enables cross-dataset comparisons of protein abundance, also providing the means to store and analyze proteomics data. However, it is currently focused only on Human datasets and since it is a centralized resource, it is not possible to store any dataset without the ProteomicsDB’s approval and intervention. Other LIMS (Laboratory Information Management System)-like systems, such as colims (CompOmics-LIMS), an improved version of the ms_lims <sup><a href="#R18" class="usa-link" aria-describedby="R18">18</a></sup> system, provides a SQL panel to directly query over the database which could go further into the data retrieved. However, this requires having knowledge about the SQL syntax as well as the database structure. OpenBIS <sup><a href="#R19" class="usa-link" aria-describedby="R19">19</a></sup> (Open Source Biology Information System) is designed to manage, annotate and share data measured in biological experiments. However, the integration of the datasets is done in a more general level, dealing with materials, methods and experiments, but not digging into the details of the actual data from the results.</p>
<p id="P6">Here we present a complementary tool, PINT (Proteomics INTegrator) that focuses only on proteomics final results, and that provides a comprehensive integration of the data (proteins, peptides and all features associated to them), and metadata (experimental design information) so that they can be used together in proteomics-specific queries.</p>
<p id="P7">Another common task in proteomics is the selection of subsets of proteins that share a certain annotation, like a conformational feature or functional domain, a protein interaction, a cellular process or pathway, or their involvement in any disease or cellular malfunction. PINT is also capable of integrating publicly available protein annotations with the stored proteomics data, improving the ability to mine existing datasets and finding additional discoveries.</p>
<p id="P8">We designed PINT as a local repository for storing, sharing and querying results originally obtained from different proteomics experiments in a laboratory. PINT is an open source Java web application that provides a long-term storage of data, including the link between experimental design and results, thus providing a powerful query system designed specifically for proteomics. All data stored in PINT can be visualized through a highly interactive web interface, facilitating its accessibility, visibility and dissemination. The tool can be visited through the webpage (<a href="http://pint.scripps.edu/" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">http://pint.scripps.edu</a>) and is available to be installed and serve as a local repository for any laboratory at <a href="https://github.com/proteomicsyates/PINT" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/proteomicsyates/PINT</a>.</p></section><section id="S2"><h2 class="pmc_sec_title">2. MATERIALS AND METHODS</h2>
<section id="S3"><h3 class="pmc_sec_title">2.1. The data model, database and web interface</h3>
<p id="P9">One of the main challenges in data management in proteomics is the great heterogeneity of the data due to the huge variety of experimental approaches. Different types of mass spectrometers may generate different types of data, which may need to be analyzed with different computational pipelines. On the other hand, the existence of different MS-based relative quantification techniques, often require different data analysis approaches, including the averaging of protein expression ratios or the statistical assessment of the significance of the relative abundance changes of the peptides or proteins among multiple conditions. Therefore, a data model for the appropriate handling and understanding of this great variety of proteomics results must be flexible enough to support any experimental setup, but at same time must not lose any information that may play a key role in the interpretation of the experimental results and that may be necessary to filter the data in further analysis. With this in mind, the data model of PINT was designed to represent any experiment including the final results linked to the experimental design, including qualitative and quantitative protein and peptide features as well as statistical confidence values, and any additional manual annotation that the author may want to associate to the dataset (<a href="#F1" class="usa-link">Figure 1</a>).</p>
<figure class="fig xbox font-sm" id="F1"><h4 class="obj_head">Figure 1: PINT architecture schema.</h4>

<figcaption><p id="P44">The schema of the architecture designed for the PINT platform is shown here. The database is based on mySQL and it is accessed by Hibernate in Java. Protein annotations and information from the database are represented in our proteomics data model which becomes accessible to the users by a query engine that translates the objects in the model to paginated lists of lightweight objects ready to be visualized in the client browser using JavaScript generated by GWT.</p></figcaption></figure><p id="P10">All experimental data is stored in a relational database. It provides a long-term scalable storage system and a way to access and filter the data. Our original database implementation is in MySQL (version 5.7.17, Oracle Corp., <a href="https://www.mysql.com/" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://www.mysql.com</a>), but other PINT users can use other database engines. The database schema, the design of the tables and relations between them, and a SQL script that will automatically create the database structure, are shared in the package. They are also accessible from the links available in the “Install PINT database” wiki section (<a href="https://github.com/proteomicsyates/PINT/wiki/How-to-install-PINT#install-pint-database" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/proteomicsyates/PINT/wiki/How-to-install-PINT#install-pint-database</a>). The database design is reflecting the data model, with some optimizations for improving the performance on the queries. To access the database, we used a combination of predefined static queries and the Hibernate framework (version 5.0) an ORM (object-relational mapping) for Java that maps the tables of the database to Java classes and the rows in the tables to Java objects.</p>
<p id="P11">PINT has been designed as a web application, accessible from any computer in the same network. Its web interface is based on GWT (Google Web Toolkit, <a href="http://www.gwtproject.org/" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">http://www.gwtproject.org/</a>), an open source project for the development of JavaScript front-end applications in Java compatible with any browser. The core of PINT has been developed in Java 1.8 and therefore it is compatible with any computational platform, and its installation is straightforward. Our PINT server is accessible from <a href="http://pint.scripps.edu/" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">http://pint.scripps.edu</a> and is open to the public, providing storage for our finished proteomics projects and open access to the public for projects that are already published.</p>
<p id="P12">All the source code is shared through a permissive license Apache 2.0 and available to download from its GitHub web page (<a href="https://github.com/proteomicsyates/PINT" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://github.com/proteomicsyates/PINT</a>), where a wiki web page can be found to help the users to install and use the software.</p></section><section id="S4"><h3 class="pmc_sec_title">2.2. Integrated external tools, resources and annotations</h3>
<p id="P13">The modular design of the source code implementation in PINT facilitates its maintenance, the development of additional features and the integration of external tools. As an example, two enrichment analysis tools are integrated into the web interface of PINT. One of the tabs from the dataset view of PINT includes the PSEA-Quant tool, a protein set enrichment analysis for label-free and label-based protein quantification data sets <sup><a href="#R20" class="usa-link" aria-describedby="R20">20</a>, <a href="#R21" class="usa-link" aria-describedby="R21">21</a></sup>. Its integration is based on a direct call to the http POST service that PSEA-Quant provides, which submits the quantitative values of a list of proteins across several replicates. The results are sent by email to the user. Another tab in the dataset view of PINT consists of the Reactome pathway enrichment analysis and pathway browser <sup><a href="#R22" class="usa-link" aria-describedby="R22">22</a>, <a href="#R23" class="usa-link" aria-describedby="R23">23</a></sup>. Reactome is an open-access, manually curated and peer-reviewed pathway database that additionally provides bioinformatics tools for the visualization, interpretation and analysis of pathway knowledge. In this case, its integration is based on the inclusion of the GWT widgets and the use of the Pathway Analysis service (<a href="https://reactome.org/AnalysisService/" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://reactome.org/AnalysisService/</a>) provided by the Reactome project. This enables the query and visualization of the latest release of the Reactome database directly from PINT.</p>
<p id="P14">Additionally, PINT includes some direct queries to external resources through their respective REST web services such as the IntAct Molecular Interaction database <sup><a href="#R24" class="usa-link" aria-describedby="R24">24</a></sup> (<a href="https://www.ebi.ac.uk/intact/" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://www.ebi.ac.uk/intact/</a>). PINT queries the binary interactions of a protein in the repository. PINT also queries whether a protein is described to be involved in a macromolecular complex as described by the Complex Portal, a manually curated encyclopedic resource of macromolecular complexes <sup><a href="#R25" class="usa-link" aria-describedby="R25">25</a></sup>. Finally PINT can also verify whether proteins or peptides have been included in any cluster in the PRIDE Archive <sup><a href="#R14" class="usa-link" aria-describedby="R14">14</a></sup>, using PRIDE Cluster <sup><a href="#R26" class="usa-link" aria-describedby="R26">26</a>, <a href="#R27" class="usa-link" aria-describedby="R27">27</a></sup>, a resource and web service provided by the PRIDE-EBI team that clusters all MS/MS spectra submitted to the PRIDE repository <sup><a href="#R14" class="usa-link" aria-describedby="R14">14</a></sup>.</p>
<p id="P15">Protein annotations are regularly updated and automatically associated with the proteins that are stored in the database. UniprotKB <sup><a href="#R28" class="usa-link" aria-describedby="R28">28</a></sup> annotations are efficiently retrieved and stored on the server in XML format using the Web Services from EMBL-EBI Services <sup><a href="#R29" class="usa-link" aria-describedby="R29">29</a></sup> and PINT regularly checks for new releases that occur approximately every 4 weeks. OMIM (Online Mendelian Inheritance in Man)<sup><a href="#R30" class="usa-link" aria-describedby="R30">30</a></sup> annotations, that is, the gene-disease associations stored in the OMIM database, are retrieved via the programmatic API access using an API key obtained after user registration at <a href="https://omim.org/api" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://omim.org/api</a>. Every time a dataset is loaded at the dataset view of PINT, the proteins will be mapped on the fly to the latest available annotations from these two resources.</p>
<p id="P16">Protein entries in PINT are identified by UniProtKB accessions. Non-UniProtKB proteins stored in PINT such as International Protein Index (IPI) or NCBI’s Gene ID (gi) entries will be mapped, if possible, to UniprotKB entries using mapping tables. In every new release of UniprotKB some protein entries may be marked as obsolete and removed or merged to other entries. PINT takes care of these issue by keeping the accessions of the proteins in its database up-to-date, always showing the latest UniProt protein entry accession, even when the protein was originally submitted with an obsolete accession. In this case, the obsolete accession becomes a secondary accession.</p></section></section><section id="S5"><h2 class="pmc_sec_title">3. RESULTS</h2>
<section id="S6"><h3 class="pmc_sec_title">3.1. Importing data into PINT</h3>
<p id="P17">In order to import new datasets into its database, the user needs to describe some metadata related to the experimental design associated with the resulting protein and peptide lists. Compared to the metadata that is required by ProteomeXchange to perform a submission, PINT focuses more into the actual experimental design metadata (experimental conditions, replicates, etc.), which could be used in a data query even for a single dataset, and not (at least for now) in other type of metadata such as the mass spectrometer used. PINT provides an import dataset wizard guiding the user step by step in which the user will have to upload the input data files and then to define certain items and set the relationships between them (<a href="#F2" class="usa-link">Figure 2</a>). The main items in the experimental design are: <em>experimental conditions</em>, <em>samples</em>, <em>experiments or replicates</em>, <em>ratios between experimental conditions</em> and <em>identification lists</em> and <em>abundance lists</em>. Additional items such as <em>sample origin (tissue/cell type)</em>, <em>organisms</em> or <em>labels</em> need to directly be associated with each <em>sample</em> item.. So, to import a dataset, the user must: 1) upload the input files and define the elements to extract from them (in case of Excel tables), 2) define the experimental design items of the project, 3) and define the relationships between the main items in the experimental design and the input files.</p>
<figure class="fig xbox font-sm" id="F2"><h4 class="obj_head">Figure 2. Graphical user interface from the import dataset wizard.</h4>
<p class="img-box line-height-none margin-x-neg-2 tablet:margin-x-0 text-center"><a class="tileshop" target="_blank" href="https://www.ncbi.nlm.nih.gov/core/lw/2.0/html/tileshop_pmc/tileshop_pmc_inline.html?title=Click%20on%20image%20to%20zoom&amp;p=PMC3&amp;id=8278777_nihms-1718947-f0003.jpg"><img class="graphic zoom-in" src="https://cdn.ncbi.nlm.nih.gov/pmc/blobs/1cd5/8278777/d04f4f64fcc4/nihms-1718947-f0003.jpg" loading="lazy" height="706" width="1050" alt="Figure 2."></a></p>

<figcaption><p id="P45">The import dataset wizard is composed by several steps (A). The user can go forwards and backwards through the different steps of the wizard with the button bar at the bottom (B). The user can save the progress any time and use the save configuration file to start from the point he left it (C). To guide the users, there are some examples of popular experimental designs. These examples are presented in the wiki web page, but to illustrate the differences, we briefly describe here two examples:</p>
<ul id="L1" class="list" style="list-style-type:disc">
<li><p id="P19">Suppose that we a user wants to import a quantification experiment with three replicates, using 6-plex TMT, in which the first three labels are the three replicates from one condition and the last three labels are the three replicates of another condition. The final relative abundance ratios are provided at the protein level with <em>p</em>-values and <em>q</em>-values assessing differential expression across the conditions associated with them. The user also has a file listing peptide identifications and another file listing the proteins associated with their final quantitation and statistical values. The user would have to define the following items: 2 <em>experimental conditions</em>, 2 <em>samples</em>, 1 <em>experiment</em> and 1 <em>ratio</em> between the two experimental conditions. Then, each <em>sample</em> has to be associated to a different <em>experimental condition</em> and both <em>input files</em> are associated to both <em>experimental conditions</em> and the <em>experiment</em>. Finally, to define the quantitative ratio, the user must select the input file with the proteins and ratios. When custom excel tables are used as input files, the user will have to define which columns to use and what their content is, such as the columns describing the peptide sequences, protein accessions, ratio values, or associated scores or statistical values, i.e. <em>p</em>-values or <em>q</em>-values.</p></li>
<li><p id="P20">As another example, suppose that a user is importing a phosphoproteomics experiment in which a sample was analyzed under two different experimental conditions in triplicates, and that a single relative abundance ratio between two conditions was obtained for each identified phosphorylated peptide sequence. Say that the user has one Excel file with the peptide-level ratios for each of the three replicates in three columns. In this case, if the user wants to incorporate the ratios per replicate, they will have to be split in Excel sheets. Then, the items to define would be: 2 <em>experimental conditions</em>, 2 <em>samples</em> and 3 <em>replicates</em>. Then, for each of the Excel sheets a <em>ratio</em> at peptide level will be defined between the 2 <em>experimental conditions</em>, and each of the sheets will be associated with a different <em>replicate</em>.</p></li>
</ul>
<p id="P21">PINT guides the user through these steps in which the semantic information about the data contained in the input files is defined (<a href="#F2" class="usa-link">Figure 2B</a>). The progress of the dataset import can be saved at any moment in a file that can be used to start from the configuration that was saved previously (<a href="#F2" class="usa-link">Figure 2C</a>). This greatly accelerates the import of subsequent experiments with similar experimental design but different results. A list of some common experimental design configurations is available to download from the starting import dataset page to facilitate new users the import of new datasets.</p>
<p id="P22">Currently PINT supports most of the common proteomics data files generated in the Integrated Proteomics Pipeline (IP2) software suit (Integrated Proteomics Applications, Inc). For protein and peptide identification data, resulting data files from DTASelect <sup><a href="#R31" class="usa-link" aria-describedby="R31">31</a>, <a href="#R32" class="usa-link" aria-describedby="R32">32</a></sup> (i.e. DTASelect-filter.txt), a post-identification processing tool for assessing the confidence of the results of search engines such as ProLuCID <sup><a href="#R33" class="usa-link" aria-describedby="R33">33</a></sup> or SEQUEST <sup><a href="#R34" class="usa-link" aria-describedby="R34">34</a></sup>, are supported. For quantitative data, output files from Census <sup><a href="#R35" class="usa-link" aria-describedby="R35">35</a></sup>, a quantification tool are also supported, including the ones coming from a novel isobaric isotopologue labelling <sup><a href="#R36" class="usa-link" aria-describedby="R36">36</a></sup> (i.e. census-chro.xml). Additionally, the HUPO-PSI <sup><a href="#R37" class="usa-link" aria-describedby="R37">37</a></sup> standard data format for proteomics results, mzIdentML <sup><a href="#R38" class="usa-link" aria-describedby="R38">38</a></sup>, is also supported. However, custom algorithms, often not published, as well as additional and manually applied analysis steps are usually performed to analyze the data as part of the whole data analysis pipeline. Although these additional “non-standard” steps may be also described in the publications associated with the data, they make their handling difficult and complicates the interpretation of the data in an automatic fashion due to their heterogeneity. They also complicate the full integration of the data in public repositories such as the ones in the ProteomeXchange consortium <sup><a href="#R9" class="usa-link" aria-describedby="R9">9</a></sup>, considering that the final results of numerous proteomics studies are published in non-standard data files or custom formatted tables. Under these circumstances, PINT recovers these results that would have otherwise been kept out of the range of most bioinformatics analysis pipelines, by supporting Excel tables as input data files. When using these types of files, PINT shows the headers of the columns of the table, so that the user can select which columns need to be imported and they can be interpreted accordingly (<a href="#SD1" class="usa-link">Figure S1</a>).</p>
<p id="P23">Once all aspects of the experimental design are defined as well as input data files and the minimum information for its interpretation are properly provided, the dataset is automatically aggregated and incorporated in the database. The new dataset will become available through the web interface as a new project. By default, datasets will remain private, only accessible by an encoded URL, unless data owner makes them public.</p></section><section id="S7"><h3 class="pmc_sec_title">3.2. Querying proteomics datasets</h3>
<p id="P24">As previously described, PINT stores both actual proteomics data and experimental metadata in its database. That way, a single protein is always linked to the MS runs, experimental conditions and samples in which it was detected or quantified. Similarly, other entities in an MS experiment such as peptides, PSMs, associated confidence scores, etc., are always stored in the context of an experimental design. This information is available to be searched through a query system able to perform proteomics-specific filters. Furthermore, as described in Methods, PINT performs an automatic integration of external annotations, and therefore they become searchable in combination or not with the experimental design context of the data. For example, PIN queries allow the rapid identification of proteins, shared between a set of experimental conditions, with a confidence score above a given threshold that are also known to be associated with diseases, or they may contain at least one phosphorylated site.</p>
<p id="P25">Queries can be performed from the web interface through different customized filters constructed to extract the information of interest from the datasets. The filters can be combined using logical operators such as “AND” (intersection), “OR” (union), “XOR” (exclusive union) or “NOT” (negation). Applying multiple filters across the same bottom-up proteomics dataset is not a trivial task, especially when filters need to consider different elements in the datasets, that is, proteins, or peptides (<a href="#SD1" class="usa-link">Figure S2</a>). If the combination of the filters is not properly designed, the resulting protein set may vary depending on the order in which the filters are performed (<a href="#SD1" class="usa-link">Figures S3</a>–<a href="#SD1" class="usa-link">S4</a>–<a href="#SD1" class="usa-link">S5</a>). Therefore, in order to properly apply the filters, we developed a method based on the representation of peptide and protein relationships as a bipartite graph <em>G</em>=(<em>V</em><sub><em>p</em></sub>,<em>V</em><sub><em>q</em></sub>,<em>E</em>), where <em>V</em><sub><em>p</em></sub> is the set of peptides, <em>V</em><sub><em>q</em></sub> is the set of proteins, and <em>e</em><sub><em>p,q</em></sub>∈<em>E</em> is the set of all edges connecting a protein <em>v</em><sub><em>q</em></sub> ∈ <em>V</em><sub>q</sub> to a peptide <em>v</em><sub><em>p</em></sub> ∈ V<sub>p</sub>. In this representation, the logical combination of all filters <em>f</em> ∈ <em>F</em> is first applied sequentially and iteratively to all edges <em>e</em><sub><em>p,q</em></sub>, until there are no more edges that are discarded in a whole round (<a href="#SD1" class="usa-link">Figure S6</a>). Specifically, all filters are first applied to the <em>G</em>. This may result in the removal of some edges. An edge <em>e</em><sub><em>p,q</em></sub> will be discarded when the protein <em>v</em><sub><em>q</em></sub> and the peptide <em>v</em><sub><em>p</em></sub> don’t comply the logical combination of filters <em>F</em>. Each filter <em>f</em>, by definition, will be applied either to the protein <em>v</em><sub><em>q</em></sub> or to the peptide <em>v</em><sub><em>p</em></sub>. For example, the filter <em>AN</em> will be applied to only proteins, the filter <em>SEQ</em> will be applied to only peptides, and the filter <em>SC</em> will be applied either to proteins or to peptides depending on how the user define it (See <a href="#T1" class="usa-link">Table 1</a> for the list of filters). Since these removals may cause filters that were previously true, such as a protein being identified by at least 3 peptides, to become false, the filters are therefore re-applied, and this process is repeated until no more edges can be removed when applying an entire set of filters. This query system allows PINT to establish any possible logical combination of filters specifically designed to be applied to experimental proteomics features of proteins or peptides, to the experimental design, or to specific annotations coming from external resources such as UniprotKB. A comprehensive description of the available query filters is described in <a href="#T1" class="usa-link">Table 1</a>.</p>

<p id="P26">PINT offers an advanced and easy-to-use graphical user interface through the web, compatible with any web browser. The interface allows the user to select datasets from a list of available datasets and visualize them in a single page organized in different interactive tabs and tables. In the <em>project information</em> tab (<a href="#F3" class="usa-link">Figure 3A</a>), PINT will show all the experimental design characteristics associated with each of the selected projects. The user can see all of the details with regards to the experimental design, such as experimental conditions, MS runs and samples. Upon selection of one of them, PINT will show the number of proteins, genes, peptides and PSMs as well as the number of experimental conditions, samples and MS runs that are associated with that item. Then, after loading a project or receiving the results of a query, a set of tables will be dynamically shown in the <em>dataset view</em> tab. Each of these tables represent different levels of aggregation: protein groups, individual proteins and peptides. When the user selects a row at the protein group or individual protein tables, the associated peptides will be dynamically loaded in a peptide table at the bottom. All tables are sortable by any column and paginated, so that the browser can efficiently load and display large tables (<a href="#F3" class="usa-link">Figure 3B</a>). Additionally, users can customize the columns of the tables by enabling/disabling them from a list of all available columns in one of the controls on the left side of the page (<em>protein group columns</em>, <em>protein columns</em> and <em>peptide columns</em>).</p>
<figure class="fig xbox font-sm" id="F3"><h4 class="obj_head">Figure 3. Different views of a project in PINT.</h4>

<figcaption><p id="P46">(A) The project information view shows information about the selected project, such as experimental conditions, MS runs and samples. By selecting each of these project items, it will show the number of proteins, genes, peptides and PSMs associated with it. (B) The dataset view shows several tables with the actual data. In this case, a table with the proteins (top) and a table with the peptides of the selected protein (bottom). (C) List of filters/query commands available to use in the queries. The filters available to the users are shown in the top left menu, and some examples of the values allowed for the filters are also shown in menus on the left side (<a href="#F3" class="usa-link">Figure 3C</a>). These include the names of the experimental conditions, ratios, scores, and also the name of the UniProt annotation types used in the filter <em>Complex Annotation</em> (<em>CAN</em>). The results will be automatically displayed in the <em>dataset view</em> tab after being processed by the server. Proteomes are built directly upon request, meaning that depending on the peptide set the user is investigating, the proteome will be automatically created according to all the possible proteins explained by those peptides. Changing the population of peptides in the datasets by applying any of the filters may result in a distinct set of proteins explained by these peptides. PAnalyzer <sup><a href="#R39" class="usa-link" aria-describedby="R39">39</a></sup>, the protein grouping algorithm implemented in PINT, automatically clusters the proteins in protein groups depending on the uniqueness of their peptides, and distinguishes different protein group types depending on their evidences (<em>conclusive</em>, <em>ambiguous</em>, <em>indistinguishable</em> or <em>non-conclusive</em>) <sup><a href="#R40" class="usa-link" aria-describedby="R40">40</a></sup>. Thereby, depending on the peptide set retrieved by a query, proteins will be grouped differently, and different types of evidences at protein level will be shown. PINT also offers a view to display each protein group, showing the set of proteins that share peptides (<a href="#F3" class="usa-link">FIGURE 3D</a>). This feature is useful for the inspection of the analysis of samples containing different proteoforms or members of protein families, which will be shown grouped in a single row in the protein group table unless a unique peptide exists, in which case the protein will be shown separated and tagged as <em>conclusive</em>.</p></section><section id="S9"><h3 class="pmc_sec_title">3.4. Enrichment analyses in PINT</h3>
<p id="P28">Additionally, PINT includes two different enrichment analysis tools: PSEA-Quant and Reactome pathways analysis (<a href="#F4" class="usa-link">Figure 4</a>). Both are fully integrated in the interface of PINT, and able to send ad hoc queries to the corresponding analysis service with the proteins of interest to the user.</p>

The results can then be explored with the rich Reactome pathway visualization tool that is also embedded in the interface which shows all the pathways described in the Reactome repository and highlights the ones considered statistically significantly enriched in the query. With the integration of Reactome pathways analysis and Reactome pathways browser, to our knowledge, PINT is the first Reactome partner using their GWT widgets (see Reactome partners at <a href="https://reactome.org/community/partners" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">https://reactome.org/community/partners</a>), proving its rich functionality with minor migration efforts.</p></section><section id="S10"><h3 class="pmc_sec_title">3.5. Projects stored in our PINT server</h3>
<p id="P31">PINT is intended to be a local repository. For example, our group, in addition to submitting datasets in public repositories, provides our proteomics datasets through our PINT server at <a href="http://pint.scripps.edu/" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">http://pint.scripps.edu</a>. This allow external groups to more easily investigate and query the datasets produced in our group. Any laboratory is encouraged to download and install PINT to host their own datasets and to share them with the public in a richer way than with other public repositories. Nevertheless, PINT allows the users to decide whether they want to share the datasets or not. PINT can therefore also play the role of a private repository for a laboratory or for a group of laboratories involved in a common proteomics project.</p>
<p id="P32">Our PINT server hosts a number of datasets associated with works that have been published during the recent years: such as: “_CFTR_” (<a href="http://pint.scripps.edu/?project=03f24aa0391e68e4" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">http://pint.scripps.edu/?project=03f24aa0391e68e4</a>) <sup><a href="#R41" class="usa-link" aria-describedby="R41">41</a></sup>, “PALM” (<a href="http://pint.scripps.edu/?project=f302f024b4d5aa1f" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">http://pint.scripps.edu/?project=f302f024b4d5aa1f</a>) <sup><a href="#R42" class="usa-link" aria-describedby="R42">42</a></sup>, “DmDshybrids2014” (<a href="http://pint.scripps.edu/?project=be0e9d3b59caf982a1c02edef0468d57" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">http://pint.scripps.edu/?project=be0e9d3b59caf982a1c02edef0468d57</a>) <sup><a href="#R43" class="usa-link" aria-describedby="R43">43</a></sup> or “Alzheimer” (<a href="http://pint.scripps.edu/?project=3d7c1ac078930a798a07c6a397bd21ef" class="usa-link usa-link--external" data-ga-action="click_feat_suppl" target="_blank" rel="noopener noreferrer">http://pint.scripps.edu/?project=3d7c1ac078930a798a07c6a397bd21ef</a>) <sup><a href="#R44" class="usa-link" aria-describedby="R44">44</a></sup>. More information about each of these projects can be found in the <a href="#SD1" class="usa-link">Supporting Information</a>.</p></section></section><section id="S11"><h2 class="pmc_sec_title">4. DISCUSSION</h2>
<p id="P33">Here, we presented a user-friendly web application that is able to store almost any proteomics experiment regardless of its complexity. Unlike currently available public proteomics-specific repositories, PINT keeps the experimental design tightly linked to the proteins and peptides stored, so that richer and more elaborate queries can be done over the datasets stored. In addition to that, we automatically link each stored protein to its annotations in UniprotKB so that datasets can be filtered by selecting protein annotations of interest. The web user interface allows the user to efficiently load, query and explore big datasets, providing fully customizable tables for proteins and peptides that can be sorted by any column.</p>
<p id="P34">PINT it is not intended to replace any public proteomics data repository Firstly, PINT is not intended to exist as a unique online instance, and rather it is designed to be a system that can be installed by any laboratory to store, share and dig more in detail the datasets created in such laboratory. Then, although one of its main features is to share datasets to the scientific community, PINT doesn’t accept raw data files as all the proteomics repositories do, not only because it doesn’t perform any data processing with them, but also because it is focused on the actual results of the experiments. Furthermore, to store raw files, would require a storage infrastructure in the backend that would limit its usage. Additionally, PINT provides a proteomics-specific query system that is not provided by any of the public proteomics repositories. Currently, PINT is limited by its persistence module (database and access to it) in order to manage the number of datasets that are, for example, stored at PRIDE (currently 89,728 assays). As an open source project, PINT is constantly evolving. We intend on incorporating new features on a constant basis, such as new query options, new columns in the data view tables and new protein or peptide annotations. We will support additional available external analysis services, database queries or portable visualization tools that will make PINT more comprehensive and useful for the exploration of proteomics datasets. Additionally, we plan to also support standard data format files, such as the ones defined in the HUPO Proteomics Standards Initiative <sup><a href="#R38" class="usa-link" aria-describedby="R38">38</a>, <a href="#R45" class="usa-link" aria-describedby="R45">45</a></sup>, as input data files, which will also facilitate the incorporation of more datasets from the proteomics community.</p></section><section id="SM1"><h2 class="pmc_sec_title">Supplementary Material</h2>
